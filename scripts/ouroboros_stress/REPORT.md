# Ouroboros 压测报告（当前参数）

模型 `sim.py` 按 `OuroborosMint.mintL2` 的实际顺序：先卖出累计的买入税（单次上限池子 0.1%），校验单笔支付不超过池子 USDT 的 10%，20% 进金库、80% 买入再加池，再按**加池后**的池价计算得币（×1.01），最后从池子等量销毁。Pancake V2 手续费 0.25%；L2 起买入税 1.25%、卖出税 1% 销毁；每个 ID 在 L1 + L2 合计 30 份。单笔超过上限时，模型把份数拆成多笔。

运行：`python sim.py`（合约现状）、`python sim.py --pre-lp`（修复前：按加池前池价计算、无上限），结果在 `results*.csv`；`python sandwich.py` 同理。

## 情景

| 情景 | 含义 |
|---|---|
| `l1_10_l2_20_hold` | 全部 ID 在 L1 各 10 份、L2 各 20 份，不卖 |
| `l1_20_l2_10_hold` | L1 各 20 份、L2 各 10 份，不卖 |
| `l1_30_only` | L1 各 30 份，没有 L2 |
| `l2_half_dump` / `l2_full_dump` | 每笔 L2 铸造后立即卖出 50% / 100%（忽略 180 秒锁定，偏悲观） |
| `thin_l2` | 只有 20% 的 ID 参与 L2 |
| `stop_then_dump` | 30% 的 ID 参与 L2 后停铸，所有持仓再卖出 80% |
| `l1_cold_l2_hot` | 只有 20% 的 ID 参与 L1，L2 全部 ID 打满 |

## 结果（1,000 个 ID）

| 情景 | 开盘池 USDT | 峰值 / 开盘价 | 期末 / 开盘价 | 期末供应 |
|---|---:|---:|---:|---:|
| `l1_10_l2_20_hold` | 7,200 | 25.1x | 25.1x | 100% |
| `l1_20_l2_10_hold` | 14,400 | 3.2x | 3.2x | 100% |
| `l2_half_dump` | 7,200 | 8.2x | 8.2x | 99.68% |
| `l2_full_dump` | 7,200 | 0.24x | 0.24x | 96.73% |
| `thin_l2` | 7,200 | 2.6x | 2.6x | 100% |
| `stop_then_dump` | 7,200 | 3.8x | 0.24x | 99.37% |
| `l1_cold_l2_hot` | 1,440 | 1,632x | 1,632x | 100% |

L1 每份 0.9 USDT，L2 阶梯起步 1.20 USDT/份。价格倍数主要取决于 L2 单价与 L1 单价之比，以及 L1 与 L2 份数之比。

- L1 份数越多、L2 份数越少，L2 对价格的推动越小；L1 冷、L2 热时价格倍数极大，但开盘池很浅。
- 停铸后集中卖出可跌到开盘价的约 0.25 倍；每笔全卖可跌破开盘价。
- 所有情景供应量 ≤ 210 亿，L2 期间不增发。
- 10% 上限只在池子被抽干时生效（10,000 ID 每笔全卖）；1,000 ID 的所有情景没有份数被拦。
- 池子至少 12 USDT 才能铸 1 份 L2（L1 至少 17 份），至少 360 USDT 才能单笔铸满 30 份（L1 至少 500 份）。

## 已修复：铸造后立即卖出的套利

修复前，得币按**加池前**的储备计算，卖出时池子已经多了 80% 的支付，价格更高，收益约为 `0.8 × 支付 / 池子 USDT − 0.25%`，池子越浅越大，资金来自池子 USDT。

下表在修复时按旧单价（L1 0.8、L2 起步 0.80）测得；套利只取决于单笔支付与池子 USDT 之比，换成现行单价结论不变。

| 条件 | 修复前单笔最大收益 | 合约现状 |
|---|---:|---:|
| 1,000 ID，正常 | −0.06% | −0.26% |
| 100 ID（开盘池 640 USDT） | +1.77% | −0.23% |
| 100 ID，L1 冷 L2 热 | +9.89% | −0.20% |
| 10,000 ID，每笔全卖 | +54%（池子被抽干） | −0.20% |

## 已修复：同一笔交易内压价铸造（`sandwich.py`）

`tx.origin == msg.sender` 拦得住合约，拦不住 EIP-7702 账户在一笔交易里连续调用：先卖出压低池价，再铸造，最后买回。收益按多得代币卖回期末池子计，占铸造支付的比例：

| 池子 USDT | 单笔支付 | 修复前 | 合约现状 |
|---:|---:|---:|---:|
| 640 | 16 | −0.09% | −0.10% |
| 640 | 120 | +30.3% | 超过 10% 上限，不可铸 |
| 6,400 | 120 | −0.13% | −0.13% |
| 6,400 | 443 | −0.01% | −0.03% |
| 64,000 | 443 | −0.39% | −0.39% |

压价会让池子 USDT 变少，上限随之收紧，压得越深越铸不出。

### 单笔上限怎么定

单笔支付占池子越大，压价套利越有利可图。按加池后计价、扣掉税和手续费，各上限下的最坏情况收益：

| 单笔上限 | 最坏情况收益 |
|---:|---:|
| 5% | −0.042% |
| 8% | −0.020% |
| **10%（现行）** | **−0.013%** |
| 12% | −0.008% |
| 15% | −0.003% |
| 20% | +0.17% |
| 30% | +1.95% |

15% 到 20% 之间开始有利可图。现行 10% 与临界点之间留有一倍余量。Foundry 测试 `test_depressThenMintDoesNotPay` 与 `test_mintThenSellRoundTripLoses` 在合约上验证了这两点。
