## 0. 本次重写修正了什么

上一版白皮书有若干处与代码不符。其中三处不是数据偏差，而是**机制被写反了**，必须单独列出，因为按上一版理解协议会得出相反的结论：

| 上一版的说法 | 代码里的事实 |
|---|---|
| 阶梯国库托管募集资金，币价踏上预设阶梯后**项目方分批提取开发资金**（"以交付换流动性 / Proof of Delivery"） | `ToshLadderTreasury` **没有 `withdraw`、没有 `sweep`、没有 `rescue`、没有 `delegatecall`**，源码里写明 "absent by design"。唯一的出金路径是 `_buyAndBurn`，收款地址硬编码为 `0xdead`。**任何人都提不出一分钱**，项目方、owner、工厂都不行。募集资金也不进国库。见 §3.4 |
| 挂载于 **Uniswap v4** 的 Hook；TWAP 来自 Uniswap v4 | BSC 上没有 Uniswap V4。协议挂在 **PancakeSwap Infinity** 的 `CLPoolManager` + `Vault` 上，结算模型不同（见 §5.1） |
| 协议手续费用于**回购并销毁 $BEM** | 国库买的是**项目自己的代币**并销毁到 `0xdead`。BEM 是被**花掉**的弹药，不是被销毁的标的。见 §4.3 |

其余修正（数据与流程层）：

- **单地址硬顶不是 0.1 ETH**，是 `46.4 BEM`（`maxPogAllocationLimit`，8 位小数）。
- **PoG 扫描的五条链是 Ethereum、Arbitrum、Optimism、Base、Robinhood Chain (4663)**，**不含 BSC**。这一条直接推翻了上一版的飞轮：TapeOut 在 BNB Chain 上，而 BNB Chain 的 Gas **当前不计入配额**。见 §6.2。
- **创世期不是联合曲线**。Phase 1 是固定价格的存入轮；4,000 级价格阶梯是 Phase 2，在二级池**已经存在之后**才开始。"曲线灌满→毕业进池" 恰恰是本协议明确拒绝的模型，见 §3.1。
- **募集不存在"达标"这回事**。创世窗口总是走到时间终点，`launch()` 由创建者调用。`defaultSoftCap` 既不是触发条件也不是失败条件，链上没有任何一处 `require` 拿募集额跟它比较——它现在也已从前端全部撤下，不再以"进度目标""募资目标""最低募集额"等任何名义出现。见 §3.2。
- **BEM 不是项目方逐项目可选的计价资产**，而是三个合约上的 `immutable`，全平台唯一、无 setter。见 §4.1。
- **"超出底池的募集资金转入国库" 不存在**。资金分配见 §3.2。

## 1. 摘要

链上资产发行有两个各自独立、但常被混为一谈的失效点。Tosh 分别用两套机制处理，且两者都不依赖治理投票或运营裁量。

**创世期的女巫与特权寻租。** 白名单、社交裂变、持币加权都无法证明真实链上行为，只会把配额让给脚本农场。Tosh 的配额由**跨五链的历史 Gas 真金白银支出**确定性度量（Proof of Gas），零白名单、零持币加权、零优先通道，另加单地址全局硬顶。伪造成本等于在一条本协议无法控制的链上真实烧掉同等 Gas。

**发射后的单向抽水。** 通行模型是"曲线灌满即达市值顶峰，然后毕业进池"，一级发行在二级市场开盘的那一刻结束，此后只剩抛压。Tosh 不这么做：**一级发行与二级市场长期并存**。发射后 4,000 级价格阶梯仍在按固定的、逐级抬升的价格出售新供应量，形成一条永久的**递增供给曲线**——价格越高，可售供应量越多，这在结构上抑制了单向暴涨。

承接这一切的是 `ToshLadderTreasury`：一个**单向阀**。协议摩擦收入流进去，只有一条出路——在项目自己的池子上市价买入该项目代币，销毁到 `0xdead`。没有提款函数。国库不是团队的钱包，它是一台焚化炉。

计价资产是 **BEM**（8 位小数 ERC-20）：募资、底池一侧、回购弹药，全部以 BEM 计价，BNB 只用于付 Gas。

## 2. 问题定义

### 2.1 零成本女巫与无法验证的"真实用户"

要在不出卖用户隐私（零 KYC）的前提下消除女巫，唯一可用的物理度量衡是**不可撤销、不可伪造、已经支付**的链上支出。持币快照可以借贷，社交图谱可以批量注册，只有历史 Gas 是已经烧掉的钱。

一个门槛让度量本身有意义。没有门槛，第二个身份的成本就是一个新地址，于是配额由**人头**而非由**成本**分配，一个今早创建的钱包与一个付了三年手续费的钱包同权。有门槛，一次申领的成本就是门槛的成本，而这笔成本是在一条本协议无法控制的链上公开支付的。

### 2.2 "毕业即顶峰"是模型缺陷，不是执行问题

联合曲线型发射台的结构是：曲线灌满 → 迁移进池 → 一级发行结束。这个结构决定了代币开盘即达市值顶峰——因为此后**再也没有新的、更贵的供应量进入市场**，唯一的价格发现方向是向下寻找支撑。团队跑路只是这个结构的一个推论，不是根因。

因此 Tosh 的对策不是锁仓或归属期（vesting），而是改结构：让一级发行在二级市场存在期间**继续运行**，且价格逐级上行。

## 3. 核心机制

### 3.1 五个阶段，以及"阶梯"一词的确切含义

| 阶段 | 内容 | 触发方 |
|---|---|---|
| Phase 1 · 创世 | 凭 PoG 签名以 BEM 固定价存入，无曲线 | 参与者 |
| Phase 2 · 发射 | 注入 Infinity CL 池，开盘可交易 | 创建者调用 `launch()` |
| Phase 2b · 上榜 | TWAP 成熟后，代币可被加入回购名册 | owner 调用 `addLadderToken` |
| Phase 3 · 交易 | 二级市场买卖，摩擦收入流入国库 | 任何人 |
| Phase 4 · 阶梯铸造 + 回购 | 4,000 级货架继续出售新供应；国库搭便车买入并销毁 | 任何人 / `afterSwap` |

**"阶梯（Ladder）" 在本协议里指两件事，都不指资金解锁时间表**：

1. **发行阶梯**：`TIER_COUNT = 4000` 级货架，每级 `TIER_SIZE = 3,150` 枚，价格逐级抬升。这是 Phase 2 之后的一级发行。
2. **回购名册**：国库轮转买入的代币列表（`addLadderToken` 登记）。

上一版把"阶梯"读成了"团队资金的分层解锁"，代码里没有这个东西。

### 3.2 创世与发射：资金到底去了哪里

**创世（Phase 1）。** 项目在 `ToshFactory.createLaunch` 发起，创建者选择窗口时长（3 小时 / 24 小时 / 72 小时）。参与者携带 PoG 签名，在自身配额 `Q(A)` 与单钱包上限内以 BEM 存入。价格固定，先后存入无价差。

**一个钱包对一个项目只存一次。** 重复存款的闸门是 `cooldownDuration`，一个按 (钱包, 项目) 计的冷却时钟，当前为 **72 小时**——不短于最长的那档创世窗口。于是第二次存款的可行时间窗恒为空集：冷却结束的时刻不可能早于它必须赶在之前的创世截止时刻。这对三档窗口一律成立，且在最紧的情形（72 小时窗口、首笔存款落在项目创建的同一个区块）下两个时刻正好相等，仍然不通过，因为存款要求严格早于截止时间。

对参与者而言这意味着**输入的金额是终局的**：它不是首付，之后没有补仓的机会，未用满的额度也不会以任何形式退回。协议不对这个选择做任何提示或兜底。

**没有软顶。** `defaultSoftCap`（默认 `928.4 BEM`）仍是工厂的一个档位，并且仍会在创建时冻进 Hook 克隆体的 immutable 参数——因此它仍然参与决定 CREATE2 地址。但除此之外没有任何代码读它：`launch()` 不查，`canRefund()` 不查，存款不会在它那里停下，远未触及它的募集照常发射。它已从前端全部撤下，界面上只剩"已筹金额 + 剩余时间"，不再有进度条与百分比。

`launch()` 真正会拒绝的只有两种规模：空募集（`totalNativeDeposited == 0`，无法注入底池），以及小到无法构造单调阶梯的募集（`RaiseTooSmallForLadder`，实测约 21 BEM）。两者都与软顶无关。

窗口一律走到时间终点，之后创建者才可以调用 `launch()`。

**两条退款通道，各自的时钟不同**，因为它们是两种不同的失败：

| 失败 | 退款开放时刻 | 它是否指向创建者 |
| --- | --- | --- |
| 募集撑不起阶梯 | 创世截止的那一刻 | 否。这笔募集在算术上就不可能 `launch()`，创建者从头到尾无事可做。事件为 `GenesisFailed`。 |
| 创建者没有发射 | 7 天 `LAUNCH_WINDOW` 走完之后 | 是。这一轮本可以开池却被放着。事件为 `ZombieRefund`。 |

第一种不需要等。存款在截止时刻关闭，募集额就此定格，结论也随之定格；发射窗口的意义是给创建者留出行动时间，而这种情形下没有任何动作可做。让存入者为一个已成定局的结果再等七天，是旧行为，不是安全性质。

两条通道读的都是发射门用的同一个判定 `ladderViable()`，因此一笔募集不可能既可发射又可退款，也不可能两者皆非。**任何客户端都应读 `canRefund()`，而不要用 `genesisDeadline + LAUNCH_WINDOW` 自行推导**——那样在每一轮募集不足的项目上都会比链上晚整整一周。

两种情形下退回的都是**全额** BEM，没有罚没、没有手续费；推荐佣金只在 `launch()` 时兑现，因此失败的创世不欠推荐人任何东西。这条路径由不变量 `invariant_unlaunchedHookCanPayEveryRefund` 持续验证：未发射的 Hook 在任意状态下都必须能付清每一笔退款。

**发射（Phase 2）的资金分配** —— 这是上一版最需要更正的地方。募集来的 BEM **不进国库**：

1. **10% 推荐佣金**（`REFERRAL_BPS = 1000`）先行划出，其中 80% 归项目推荐人、20% 归全局推荐人（`PROJECT_REFERRAL_SHARE_BPS = 8000`）。无推荐人的存入，这部分成为"孤儿佣金"，**流入国库**（成为回购弹药，不归任何人）。
2. **余下全部 BEM 注入 Infinity CL 池**，作为底池的 BEM 一侧。
3. **创世供应量 `GENESIS_SUPPLY = 8,400,000` 枚按 55 / 45 拆分**：`GENESIS_CLAIM_SUPPLY = 4,620,000`（55%）留给存入者按份额领取；余下 3,780,000（45%）与 BEM 一起注入全区间流动性头寸。
4. **该流动性头寸永久锁定**，没有任何代码路径能把它取出——包括 owner。

**开盘价** = 存入者平均成本的 **1.10 倍**，即存入者一开盘即处于浮盈。这个 1.10 不是可调参数，而是 55 / 45 拆分的算术推论：`(0.9 / 3.78) · 4.62 = 1.10`。Phase 2 的 0 号货架再在开盘价之上加价 5%（`SHELF_PREMIUM_BPS = 10_500`），保证一级发行永远贵于存入者的成本。

### 3.3 Proof of Gas：配额函数

零白名单、零持币加权、零优先通道。持有多少 BEM 不带来任何乘数。

离线索引器与签名预言机统计地址在五条链上的累计 Gas 支出 $G_{spent}$：

$$
Q(A) = \begin{cases}
0 & G_{spent} < G_{floor} \\
\min\left(G_{spent} \times r,\; Q_{max}\right) & G_{spent} \ge G_{floor}
\end{cases}
$$

| 参数 | 值 | 说明 |
|---|---|---|
| 扫描链 | Ethereum · Arbitrum · Optimism · Base · Robinhood Chain (4663) | **不含 BSC**，见 §6.2 |
| $G_{floor}$ | `0.025 ETH` | 低于门槛预言机**拒绝签名**，而不是签一个小数字 |
| $r$ | 每 1 ETH 历史 Gas 兑 `46.4 BEM` | 可由 owner 轮换 |
| $Q_{max}$ | `46.4 BEM`（`maxPogAllocationLimit`） | 单次签名与单钱包存入的双重上限 |

**达标不等于给满额。** 过了门槛只是进入区间，配额在 $[1.16,\ 46.4]$ BEM 之间随历史 Gas **线性放缩**：下端 1.16 BEM 对应刚好踩线的 `0.025 ETH`，上端 46.4 BEM 在**恰好 1 ETH** 的累计 Gas 处打满（这个饱和点是 `maxPogAllocationLimit` 与 $r$ 的商，两者历来同倍数调整，所以它跨过两次重新计价都没有移动）。整个区间跨 40 倍。

这一条压制批量低保号的方式值得写清楚，因为**起作用的不是线性本身**：

- 相对"达标即给满额"的二元设计，线性放缩取消了给最便宜的合格钱包的 **40 倍补贴**——原本 0.025 ETH 的 Gas 能换 46.4 BEM，现在只能换 1.16 BEM。
- 而在区间内部，拆号是**数学上完全中性**的：$N$ 个各持 $G/N$ Gas 的钱包合计拿到 $N \times (G/N \times r) = G \times r$，与单个钱包持 $G$ 完全相同。每一单位配额的 Gas 成本在全区间恒定，人头本身买不到任何东西。
- 真正惩罚拆号的是**门槛**：每个钱包必须**独立**跨过 `0.025 ETH`，所以把 0.1 ETH 拆到 10 个号上（各 0.01 ETH）会让全部 10 个号配额归零，而不是等比例缩小。

**配额也不能靠时间叠加。** 上面三点讲的是"同一时刻横向拆号"，还有一条纵向的路子：配额每 `quotaWindowDuration`（24 小时）刷新一次，而 `nativeDeposited` 记的是累计值、不随之清零。两个时钟一旦同步，一个低保号在 72 小时窗口里可以领三次配额、分三笔存入同一个项目，堆到 $3 \times 1.16 = 3.48$ BEM——线性放缩刚刚拿掉的补贴，被时间又还回去了一部分。把冷却提到 72 小时正是为了掐掉这条路：**任何钱包在任何单个项目里的持仓，上界都是一次配额抽取 $Q(A)$**（若该窗口内已在别处花掉一部分，则更少），而不是 $Q_{max}$ 在多个窗口上的累加。这一条恰好绑定在低保号身上——已经打满 $Q_{max}$ 的钱包本来就被单钱包上限挡住，不受影响。

反过来也要说明：$Q_{max}$ 是唯一让拆号变得**有利**的地方——累计 Gas 超过 1 ETH 之后，多烧的部分在单个钱包里换不到任何配额，巨鲸因此被推向拆号。这是一个自觉的取舍：上限用"让饱和钱包有动机拆分"的代价换筹码去中心化，而门槛是给这种拆分定价的那一环。

**⚠ 两个量纲不同，这是刻意的，不是 bug**：$G_{floor}$ 以 **ETH（18 位小数）** 计，因为被扫描的链都以 ETH 结算，衡量的是"烧掉的 Gas"；$Q_{max}$ 以 **BEM（8 位小数）** 计，因为衡量的是"存进来的钱"。把两者统一换算会在看起来只是改名的情况下把准入门槛抬高 3.5 倍。

签名载荷绑定 `(sender, maxAlloc, nonce, deadline, chainId, hook)`，跨项目、跨链、跨钱包均不可重放。

### 3.4 ToshLadderTreasury：单向阀

**这一节整体替换上一版的 §3.3。上一版描述的机制在代码里不存在，且方向相反。**

国库**不托管募集资金**。它的收入来自三条摩擦管道，全部是 BEM：

1. 每笔**买入**的 0.70% 在途税（`TAX_BPS = 100` 共 1.00%，其中 30 bps 归平台）；
2. 无推荐人存入产生的孤儿佣金；
3. 每次 Phase 2 货架铸造的 1% 平台抽成（`PLATFORM_TAX_BPS = 100`）。

**发射费不在其中，这是一处改动。** 它曾经是第四条，现在改以原生 **BNB** 计价（默认 `0.005 BNB`，作为 `msg.value` 随 `createLaunch` 发送，多付部分同笔退回），并转入 `platformTreasury` 而非本国库。原因是本国库只花 BEM、也没有 `receive()`，原生币进来就会永久卡死。回购弹药因此少了一条管道，但 0.005 BNB 一次发射的量级本来就远不及 70 bps 的买入税，影响可忽略。

**卖出侧的税不进国库**：那部分代币由 Hook **就地销毁**，根本不需要经过任何储备池。

**唯一的出金路径。** 每笔 swap 的 `afterSwap` 会"顺手推一下" `autoPiggybackBuyback()`。当国库余额跨过 `TRIGGER_STEP = 92.8 BEM` 时，本次 swap 就**搭一趟便车**执行回购：花掉 `max(TRIGGER_STEP, 余额 × SPEND_BPS / 10000)`（`SPEND_BPS = 1000`，即 10%），平均分配给名册上接下来 `BATCH_SIZE = 3` 个代币，在各自的池子上市价买入，所得**直接送往 `0xdead`**。

**审计可 grep 的断言**（在 `ToshLadderTreasury.sol` 中必须零匹配）：

```
function withdraw   — absent by design
function sweep      — absent by design
function rescue     — absent by design
delegatecall        — absent by design
.transfer( / .call{value  在 _buyAndBurn 之外 — absent by design
```

**这条铁律约束的是"保管权"，不是"受益人"——这个区别必须说清楚。** owner 拿不走一分钱，但 owner 决定哪些市场吸收这笔买盘，而终点是销毁的买盘依然是落在某个人订单簿上的买盘。只上一个币、把其余下架，就等于把整个储备指向单一价格。

约束它的是两个机制，都不是那条铁律本身：

- `_buybackSqrtFloor` 限定任一轮回购最多填到池子 TWAP 之上多远（`MAX_BUYBACK_SQRT_DEVIATION_BPS = 1000`，10%），使集中度被限速到大约每个 TWAP 窗口一个偏离带，无法按需抽干；
- 每币金额除以 `BATCH_SIZE` 而**不是**除以实际上榜数量，所以只有一个币的名册只会部署满员名册三分之一的速率——窄名册买到的是细流，而不是同一张支票被集中砸下。

剩下的是治理面而非代码面：名册策展应当与其他经济参数一样，置于同级别的多签与变更评审之下。本协议不声称已经解决它。

### 3.5 TWAP 成熟度保护

`TWAP_WINDOW = 1800` 秒（30 分钟）。代币上线初期预言机样本未成熟时，`addLadderToken` 会以 `TwapNotMature` 回滚，杜绝用闪电贷把瞬时价格抬起来、再借回购机制套利。回购本身也读同一条 TWAP 求价格上限。

## 4. BEM：计价资产

### 4.1 接线方式

BEM 是三个合约（`ToshFactory`、`ToshLaunchpadHook` 实现、`ToshLadderTreasury`）构造函数里的 **`immutable`**。**没有 setter，不是项目方逐项目的选项**——全平台每个项目都用同一个计价资产。更换它意味着重新部署整套合约并迁移每个池子。

**8 位小数是不变量，不是细节。** BEM 有 8 位小数而非 18 位，全部资金路径按 8 位处理，前端有独立的 `fmtQuote` 格式化函数与其分开，`preflightMainnet` 有专门的门禁（`5c`）校验链上 `decimals()` 必须为 8。历史上这条曾出过事：**币种变了这件事当时被记住了，量纲变了这件事没有。**

**BEM 必须是池子的 `currency0`。** Hook 里有 91 处逻辑依赖这个排序（买卖方向、TWAP 符号、LP 载荷编码）。`createLaunch` 通过 CREATE2 磨盐（`deployBareCloneAbove`），确定性地把项目代币的地址磨到 BEM 之上，再以 `TokenBelowQuoteAsset` 回滚兜底。

**所有资金路径都不是 payable。** `createLaunch`、`deposit`、`mintBondingCurve` 全部需要先 `approve` 再调用（两笔交易）。平台抽成收到的是 ERC-20 转账，不是原生币。

### 4.2 BEM 在协议中的三个角色

1. **募资资产**：创世期存入的是 BEM，配额上限以 BEM 计。
2. **底池一侧**：募集的 BEM 作为 `currency0` 注入 CL 池并永久锁定。项目越多，被永久锁进底池的 BEM 越多。
3. **回购弹药**：国库积累的 BEM 被花在项目代币的买盘上。

### 4.3 关于"销毁"的更正

上一版称协议手续费"回购并销毁 $BEM"。代码里不是这样：

- 国库买入的是**项目自己的代币**，销毁的是**项目自己的代币**（送往 `0xdead`）；
- **BEM 是被花掉的一侧**，它从国库流向池子，不被销毁。

因此对 BEM 的价值影响机制是**需求与锁仓**（被永久锁进底池、被持续用作买盘弹药），不是**通缩销毁**。二者是不同的经济论证，不应互相冒充。

### 4.4 选择 BEM 的代价

诚实列出，因为这是一个有成本的决定：

- **浮筹薄、供应量波动**：BEM 的 mint 权限在代理合约之后。计价资产若被暂停、拉黑或加了转账钩子，买入腿会失败——这个风险不是 Safe 的属性，是代币的属性，本协议的任何检查都覆盖不到它。
- **最小募集额被抬高**：`MIN_SOFT_CAP_PROD = 100 BEM`。
- **多一笔交易**：每条资金路径都需要先授权。

## 5. 系统架构

### 5.1 为什么是 PancakeSwap Infinity 而不是 Uniswap V4

BSC 上没有 Uniswap V4 部署。协议挂载在 PancakeSwap Infinity 上，与 V4 的差异不止是换个地址：

- **Infinity 把 V4 的 PoolManager 拆成两个合约**：`CLPoolManager` 持有池子状态，`Vault` 持有余额与锁。因此结算走 `vault.sync / transfer / settle` 三步，而不是 V4 的一次 `settle{value:}`。
- **`PoolKey` 是六成员**（多了 `poolManager` 与 `parameters`），V4 是五成员。LP 载荷的操作码与 V4 数字上完全相同，所以 **`PoolKey` 的宽度是唯一的结构性信号**——这也是为什么仓库里有跨语言元组护栏在 CI 上比对。
- **Hook 权限是位图**（`getHooksRegistrationBitmap()` 返回 `0x0CC5`），不是 V4 的地址挖矿。
- **没有 StateView**，价格与流动性直接读 `CLPoolManager.getSlot0 / getLiquidity`。

### 5.2 合约布局

| 合约 | 职责 |
|---|---|
| `ToshFactory` | 校验 PoG 签名、强制单地址硬顶、CREATE2 部署 Hook 与代币克隆体（磨盐保证代币地址高于 BEM）、收取发射费（原生 BNB，转入 `platformTreasury`） |
| `ToshLaunchpadHook` | 创世记账与退款、`launch()` 注入流动性、Phase 2 的 4,000 级货架发行、在途买卖税、TWAP |
| `ToshLadderTreasury` | 单向阀：三条管道进、仅 `_buyAndBurn` 出，收款地址硬编码 `0xdead` |
| `ToshToken` | 每项目 ERC-20，`MAX_SUPPLY = 21,000,000`，在每次 `mint` 上强制 |

**供应量结构**：创世 8,400,000（55% 存入者领取 / 45% 进底池）+ 阶梯 12,600,000（4,000 × 3,150）= 21,000,000，售罄后恰好落在 `MAX_SUPPLY` 上，而不是逼近它。

### 5.3 交易摩擦

| 项目 | 费率 | 去向 |
|---|---|---|
| 池子费 | 0.30%（`POOL_FEE = 3000`） | LP |
| 买入在途税 | 1.00%（`TAX_BPS = 100`） | 0.70% 国库 + 0.30% 平台（`PLATFORM_SWAP_FEE_BPS = 30`） |
| 卖出在途税 | 1.00% | **就地销毁** |
| 合计摩擦 | 1.30% | |

平台收款地址 `platformFeeRecipient` 在工厂与 Hook 实现里都是 **`immutable`**，轮换它等于重新部署工厂并迁移每个池子。

### 5.4 核心不变量

以下均由 Foundry 不变量测试持续验证（`forge test` 398 个测试；soak 深跑为每条不变量 256 runs × 1000 depth = 256,000 次调用，零 revert）：

- **无特权**：不存在绕过 PoG 配额直接铸造或认购的函数。BEM 大户同样必须凭自身 Gas 历史参与。
- **配额上限**：任何分支下单钱包存入总量不可越过 $Q_{max}$；`invariant_perHookCapsAreFrozen` 保证上限在发射后不可更改。
- **单项目一次存款**：`test_deposit_slowGenesisAllowsExactlyOnePerWallet` 在最紧的情形（72 小时窗口、首笔存款与项目创建同区块，两个时刻正好相等）下断言两道闸零重叠交接——截止前一秒拒于冷却，截止当刻拒于窗口关闭。⚠ 这条性质依赖 `cooldownDuration >= DURATION_SLOW`，而前者是工厂上的**可变拨盘**、后者是 Hook 上的常量，72 对 72 没有任何余量：调低拨盘或新增一档更长的窗口都会无声地让分期存款复活。`test_cooldown_isAtLeastTheLongestGenesis` 把这个关系钉成构建失败。但单元测试跑的是源码、不是**部署**——它管不住部署之后有人调拨盘，而 `setCooldownDuration` 只需一笔 Safe 交易、不 revert、不改变任何界面。事件告警 `CooldownDurationUpdated` 也不够：它分不清 72→96（无害）和 72→24（废除规则）。所以真正的控制是定时状态读取 `STATE-08`，逐小时比对 `cooldownDuration() >= DURATION_SLOW`，其中 `DURATION_SLOW` 从链上的 Hook 实现读取而非写死，这样"新增一档更长的窗口"这条漂移也一并被覆盖。
- **退款可兑付**：`invariant_unlaunchedHookCanPayEveryRefund` —— 未发射的 Hook 必须始终能付清每一笔全额退款。
- **国库只因回购而减少**：`invariant_treasuryOnlyLosesEthToBuybacks` 与 `invariant_treasuryOutflowAlwaysBurns` —— 国库的每一次出金都终结于销毁。
- **owner 不持有价值**：`invariant_ownerNeverHoldsValue`。
- **销毁不可逆**：`invariant_burnedSupplyNeverReturns`。
- **owner 不能改动存入账本**：`invariant_ownerCannotMoveTheDepositLedger`。

## 6. 生态意向：TapeOut 与 $BEM

**本节与前五节性质不同，必须分开读。** §1–§5 描述的是已在源码中、有测试覆盖的机制。本节描述的是尚未落地的意向。上一版把两者混排，其后果是把一个**不成立的**机制写成了飞轮的关键一环。

### 6.1 已经成立的部分

BEM 作为计价资产是**真实且已实现的**（§4）：募资、底池、回购弹药三个角色都在代码里，有主网分叉测试对真实 BEM 字节码验证。这一部分不是意向。

### 6.2 ⚠ 未实现：TapeOut Gas 计入 PoG 配额

上一版称开发者在 TapeOut 上搭建电路、烧录容器消耗的 Gas "原生地计入 Tosh 跨链捕获引擎"。**当前不成立，而且不是接线缺失的问题**：

- PoG 扫描的五条链是 Ethereum、Arbitrum、Optimism、Base、Robinhood Chain (4663)。
- **BNB Chain 不在其中**。TapeOut 在 BNB Chain 上，所以 TapeOut 上的交互当前产生的配额是**零**。
- 这不只是加一条链的工程量。配额函数的门槛与汇率以 **ETH** 计价（§3.3），因为被扫描的链都以 ETH 结算；把一条以 BNB 结算的链并进同一个求和，需要先决定一个 BNB/ETH 的换算口径，而任何固定口径都会随汇率漂移，任何动态口径都会把一个价格预言机引入准入路径。这是一个**设计决定**，尚未做出。
- 另有一个已知的运营障碍：Etherscan v2 的免费层对链 `56` 的 `account` 模块不开放，索引 BNB Chain 的 Gas 历史需要付费层。

代码库中 **`TapeOut` 零匹配**——没有 `TapeOut Integration Bridge`，也没有 `$BEM Sink` 合约。上一版把这两个列为核心合约布局的一部分。

### 6.3 ⚠ 未实现：资金投向 TapeOut 生态

上一版称项目方在国库中随币价解锁的资金可用于在 TapeOut 上采购元件、租赁容器。**该资金流不存在**，因为国库没有任何提款路径（§3.4）——不存在"解锁资金"这个东西。

若要实现"交付换资金"这类机制，它需要是一个**新的、独立的托管合约**，与 `ToshLadderTreasury` 并列而非等同。本协议当前不提供它，白皮书也不应预先声称它。

### 6.4 一个诚实的飞轮

删掉不成立的环节后，当前实际成立的循环是这样的：

```
        [五链历史 Gas 支出：ETH · ARB · OP · BASE · Robinhood]
                            │
                            │ 确定性配额，零特权 / 零加权 / 零白名单
                            ▼
              ┌──────────────────────────────┐
              │      Tosh 创世引擎           │
              │  以 BEM 募资，单地址硬顶      │
              │  46.4 BEM                    │
              └──────────────┬───────────────┘
                             │ 创建者 launch()：BEM + 45% 供应量
                             │ 注入 Infinity CL 池并永久锁定
                             ▼
              ┌──────────────────────────────┐
              │  二级市场（BEM / 项目代币）   │
              │  摩擦 1.30%                   │
              └──────┬────────────────┬──────┘
                     │                │
       买入税 0.70% │                │ 4,000 级货架继续按
       孤儿佣金     │                │ 递增价格发行新供应
       货架抽成 1% │                │ （一级发行不结束）
                     │                │
                     ▼                ▼
              ┌──────────────────────────────┐
              │  ToshLadderTreasury 单向阀    │
              │  无 withdraw / sweep / rescue │
              └──────────────┬───────────────┘
                             │ 余额 ≥ 92.8 BEM 时搭便车
                             │ 花 10%，分给名册上 3 个代币
                             ▼
                   市价买入项目代币 → 0xdead 销毁
```

注意这个图里**没有一条箭头指向团队钱包**。这既是设计，也是与上一版最大的差别。

## 7. 已知局限

一份不列局限的白皮书不值得据以决策。

1. **主网未部署。** 链 `56` 上没有合约。测试网 `97` 上现在跑的是 BEM 改造之后重部的一套（工厂 `0x38067B1B…C9B1`），计价资产是一枚 8 位小数的 **mock** 代币 `mBEM`（`0x76bD1ceC…82EB`）——不是真 BEM。所以 `97` 能验证机制、小数位和资金路径，唯独验证不了真实 BEM 的供应量变动与流动性深度，而那恰是 §4.4 所列的风险所在。此前那套更早的 `97` 工厂（`quoteAsset()` 会 revert、`launchFee()` 返回 0.35 BNB）已弃用，且其私钥公开、无人可管，不要拿它做任何判断。
2. **名册策展是治理面风险**（§3.4）。铁律管保管权，不管受益人。
3. **计价资产的对手方风险**（§4.4）。BEM 的 mint 权限在代理之后，其暂停或黑名单能砖化买入腿，本协议无法检查。
4. **PoG 依赖离线预言机签名。** 签名者私钥泄露等于配额可被任意签发，因此签名者轮换是上主网前的硬前置条件。
5. **Optimism 与 Base 上测得的是执行费**，不含 L1 数据费，所以这两条链的 Gas 统计**偏低**（已实测量化：Optimism 上样本平均偏低约 2.3%）。这让门槛在这两条链上略微偏严，而非偏松。
6. **TapeOut 集成尚不存在**（§6）。

## 8. 结语

Tosh 的两条主张都可以在字节码层面核验，而不必相信任何人的路线图：

**配额由已经烧掉的钱决定**，不由白名单、持仓或社交图谱决定。伪造它的成本等于在一条本协议控制不了的链上真实支付同等 Gas。

**一级发行不在开盘时结束。** 4,000 级递增价格的货架在二级市场存续期间继续供货，而协议摩擦的全部去向是一台没有提款口的焚化炉。团队拿不到托管资金——不是因为有归属期，而是因为**那条代码路径不存在**。

至于生态层：BEM 作为计价资产已经落地；TapeOut 的接入还没有。这份白皮书把两者分开写，因为把意向写成实现，是上一版最需要修正的地方。
