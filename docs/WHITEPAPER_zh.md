## 1. 摘要

ToshX 是部署在 BNB Smart Chain 上的公平发射平台。我们想解决的问题很简单：**让普通人有公平的机会参与早期项目，让认真做事的创业者能拿到第一笔钱，并且随着项目成长持续获得资金。**

为此，协议用四个写进合约的机制，分别对准四个根因：

| 根因 | 机制 | 结果 |
|---|---|---|
| 新地址零成本，额度按人头分，被批量钱包吃掉 | **Binance Agent ID**：创世和货架的额度都按 Agent ID 记账，一个 Binance 账户只能领一个，且不可转让 | 新建地址换不到额外额度；准入不依赖平台的签名服务 |
| 先到先得、越早越便宜；池子随时可能被撤 | **线性曲线创世 + 永久锁池**：创世价从 P 线性涨到 1.5P，每个 ID 有额度上限；开盘价 2P，流动性永久锁定 | 抢先的好处有上界；开盘价是平均成本的 1.6 倍；撤池在结构上不存在 |
| "毕业即顶峰"：开盘后再无新供给，项目方没有持续收入 | **持续阶梯发行**：10,000 档货架随行情逐档涨价供货；收入 80% 买入代币并永久加进池子，19% 归项目方 | 币价越高，池子越深；项目方想多拿钱，只能让币价更高——与持有人利益同向 |
| 平台金库就是团队钱包，"回购"只是承诺 | **单向回购金库**：没有提款函数，唯一出口是买入项目代币并销毁到 `0xdead` | 交易越多，销毁越多；团队和多签都动不了这笔钱 |

每个项目都拥有自己的一份 PancakeSwap Infinity Hook 合约。发行、税费、回购和开盘规则在部署时冻结，不可升级。募集资金 80% 在开盘时永久锁进池子，20% 记入项目基金；此后货架收入的 80% 也持续买币加进同一个池子，同样永久锁定。平台不托管其中任何一部分，也没有任何代码路径可以挪用它。

每个项目的代币总量是 21 亿枚：创世 2.7 亿，阶梯 18.3 亿。

## 2. 我们为什么做这件事

我们相信，融资的机会不应该只属于有关系、有名气、有 VC 背书的少数人；参与早期项目的机会，也不应该只属于跑得最快的机器人。

- **对参与者：机会平等。** 不看白名单，不看关系，不拼机器人速度。只要持有一个 Binance Agent ID，就有一份额度；价格只取决于已经卖出多少，公式写在合约里。
- **对创业者：融资平等。** 不需要先有名气。无论是加密项目，还是独立品牌、小店、工作室这样的 Web2 小企业，都应该能用同一套透明规则募资，并随成长持续获得资金。
- **对行业：信任回归。** 规则写在合约里，每一笔钱的去向都能在链上验证。我们希望 Web3 被记住的，是它帮助了多少真实的创业者。

我们还很小。但我们相信 Web3 可以变得更好，可以真正去支持更多的创业者。这份白皮书描述的，就是我们为此写下的规则。

## 3. 问题：今天的发射与融资哪里不公平

### 3.1 女巫与机器人

在零成本创建新地址的世界里，"一人一份"的额度实际上是"一个地址一份"。白名单、社交任务、持币快照都无法证明背后是一个真实的人：持币可以借，社交账号可以批量注册，任务可以用脚本完成。结果是额度被批量钱包吃掉，真实用户排在机器人后面。

### 3.2 "毕业即顶峰"

主流的联合曲线发射模型是：曲线灌满 → "毕业"迁移进池 → 一级发行结束。这个结构决定了代币在毕业那一刻就到达市值顶峰——此后再也没有新的、更贵的供给进入市场，价格唯一的方向是向下寻找支撑。团队抛售、项目跑路只是这个结构的推论，而不是根因。

### 3.3 金库就是钱包

平台和项目方收的手续费进入他们自己控制的地址，"回购""销毁"停留在承诺层面，持有人无法验证，也无法阻止资金被挪用。

### 3.4 创业者没有持续的资金来源

一次募资结束之后，项目方后续的开发资金只能靠卖币。这让项目方和持有人站在对立面：项目方越需要钱，持有人承受的抛压越大。

### 3.5 小企业融资难

Web2 小企业面对的是另一组门槛：银行要抵押，VC 只看少数赛道，众筹平台抽成高，而支持者拿到的回报既不透明，也无法流通。链上本可以提供一个透明、可验证、全球可达的替代方案，但现有的发射平台大多只为投机性代币设计。

## 4. 设计原则

1. **规则写进代码，而不是写进承诺。** 能用合约约束的，不交给运营判断。
2. **平台碰不到资金。** 流动性和回购金库没有通往任何钱包的代码路径；募集资金只按写死的比例流向池子（80%）和项目基金（20%），货架收入只按写死的比例流向池子（80%）、项目方（19%）和回购金库（1%），平台拿不到。
3. **失败的方向必须安全。** 注册表、项目基金地址或平台出问题时，受影响的只有创世买入，开盘一定能完成；买入即到账，不存在资金卡在合约里等待退款的状态。货架收入暂时加不进池子时只会排队等待，不会让货架购买失败。
4. **每个数字都有出处。** 本文的每一个参数都对应链上可读的常量或状态。
5. **紧急制动必须有边界。** 平台保留的刹车只能阻止"新增"，不能扣住任何人已经投入的资金。

## 6. 上架：平台审核制（GrantPad）

### 6.1 为什么要审核

"任何人都能一键发币"的平台，最大的受害者恰恰是普通参与者：仿盘、诈骗盘和零投入的项目会挤占所有人的注意力和资金。我们希望参与者在 ToshX 上看到的每一个项目，背后都有一个真实、经过沟通的团队——这对未来引入 Web2 小企业尤其重要。

因此 `createLaunch` 只能由平台调用。平台在链下审核项目，再把审核表上的参数写入链上。**审核决定的是"谁能上架"，不决定"谁能参与"**：上架之后，参与规则对所有人一视同仁，平台无法为任何人开后门。

### 6.2 每个项目的参数

| 参数 | 范围 | 说明 |
|---|---|---|
| 计价币 | BNB（内部为 WBNB）或 USDT | 由选择的工厂决定 |
| `hardCap`（H） | BNB 项目 1 – 500 BNB；USDT 项目 500 – 300,000 USDT | 卖完时的募集总额；第一枚价格 P = H ÷ 225,000,000 |
| `perAgentCap` | BNB 项目 0.01 – 1 BNB；USDT 项目 5 – 30,000 USDT（平台可调整范围） | 每个 Agent ID 在本项目创世期最多花多少，由项目在范围内选定 |
| `genesisDuration` | 3 小时 / 24 小时 / 72 小时 | 创世窗口时长，只有这三档 |
| `developer` | 任意非零地址 | 接收该项目的 Circuit NFT |
| `projectFund` | 任意非零地址，不能是该项目的 Hook | 接收 20% 募集资金；NFT 持有者之后可以修改，NFT 转让时自动改为买方（§12.3） |

这些参数在部署时冻结进项目合约，之后任何人（包括平台）都无法修改。同名同符号的项目只能存在一个。最小买入额为 0.01 BNB / 5 USDT。

### 6.3 不收发射费

项目方上架不需要支付任何费用。平台的收入只来自真实的交易量（§10），这让平台和项目方的利益一致：项目做得越好、交易越活跃，平台才赚得越多。

## 7. Binance Agent ID：一个身份一份额度

### 7.1 为什么用 Agent ID

v1 用历史 gas 度量钱包，需要链下扫描服务和一把签名私钥，这把私钥是整个准入流程的单点。从 v2 起，协议直接读取 BNB Chain 上的 Binance Agent ID 注册表（SPACE ID 发行的 `.ai` 名字，`0x60B9…B022F`）：

- Agent ID 不可转让、永久有效，一个 Binance 账户只能领取一个；
- 合约在买入时直接读注册表，平台不运行任何签名服务，也不保管任何准入私钥。

### 7.2 怎么校验

创世买入和货架购买时，合约依次读取：

1. `handleOf(买家)`：为空则拒绝；
2. `ownerOfHandle(名字) == 买家`：两次读取一致才算持有；
3. 额度按名字的哈希记账，而不是按地址。名字即使换绑到别的地址，也不能再领一份额度。

两次读取都限定 gas 上限。注册表出问题时只有创世买入和货架购买暂停，开盘、交易、转账和买单簿不受影响。

### 7.3 谁能参与，怎么参与

- 创世买入时，买家必须是交易的发起人：普通钱包和 EIP-7702 账户都可以，合约钱包（Safe 等）不行。
- Agent ID 绑定在 Binance Agentic Wallet 上，而 Agentic Wallet 不能连接网页。网页把每一步写成指令，用户交给自己的 AI agent，在 Binance App 的开发者模式下执行。
- 2026 年 10 月链上抽查的 555 个 Agent ID 持有地址全部是普通钱包，交易由持有者本人直接签名。

### 7.4 两份额度

| 额度 | 大小 | 说明 |
|---|---|---|
| 创世额度 `perAgentCap` | 每个项目上架时选定（§6.2） | 可以分多次买。付多了不会多扣：实际成交额 = min(支付额, 剩余额度, 卖完所需金额)，BNB 项目多付的部分在同一笔交易里退回 |
| 货架额度 `shelfCapPerAgent` | BNB 市场 0.7 BNB；USDT 市场 500 USDT | 每个 Agent ID 在每个项目的货架上终身最多花多少，与创世额度分开计算。花费同时按名字和钱包记账、取两者中较大的一个，所以换名字或换钱包都拿不到新额度。平台可以调整，调整对所有项目同时生效 |

## 8. 创世发售与开盘

### 8.1 按卖出量线性涨价

创世期最多卖出 180,000,000 枚。已卖出 s 枚时，下一枚的价格是：

$$
\text{price}(s) = P \times \left(1 + 0.5 \times \frac{s}{180{,}000{,}000}\right), \quad P = \frac{H}{225{,}000{,}000}
$$

第一枚价格为 P，最后一枚为 1.5P，卖完时平均价 1.25P，募集总额正好是硬顶 H。越早参与越便宜；每个 Agent ID 有额度上限，抢先的好处有上界。以硬顶 100 BNB 为例，P ≈ 0.000000444 BNB，1 BNB 在曲线起点约买到 222 万枚。

买入时代币立即铸给买家，没有领取步骤，也**没有退款**。剩余可售量低于 0.001 枚时视为卖完。

### 8.2 资金去向

每一笔买入当场记账：

- **20%** 记入项目基金，NFT 持有者随时可以提到 `projectFund`；
- **80%** 留作建池资金，开盘时全部进池。

记账而不是即时转账，是为了让任何地址都卡不住买入。协议不设推荐佣金。

### 8.3 开盘前：只有买单的官方市场

开盘前代币已经在用户手里，但链上不能形成任何池子。代币合约在开盘前只允许下面两种转账：

| 情况 | 条件 |
|---|---|
| 钱包之间转账 | 发送方本人发起交易；收款方是钱包（普通钱包或 7702 账户），并且已登记为收款地址 |
| 买单簿成交 | 由官方买单簿发起，卖家本人发起交易，买家是已登记的钱包 |

参与过创世或挂过买单的钱包会自动登记；其他钱包要先自己发一笔登记交易。未部署的合约地址没有私钥，永远无法登记，所以"先打币、再部署合约"的绕法不成立。开盘前也只能授权给官方买单簿。

官方买单簿（`ToshBidBook`）：

- 任何钱包都可以挂买单，资金托管在合约里，随时可撤；页面上没有卖单。
- 挂单价不得低于当时的最新参与价；成交时，价格低于最新参与价 90% 的买单会被跳过。
- 买卖双方各付 1% 手续费，只在成交时收取，归平台。
- 开盘后停止挂单和成交，只能撤单。

### 8.4 开盘

- **时间**：卖完或创世截止后，48 小时内只有 Circuit NFT 持有者可以开盘；48 小时后任何人都可以，没有过期。开盘一定能完成：它不依赖注册表、不依赖项目基金地址，也不受工厂暂停影响。
- **建池**：80% 募集资金与 `0.8H ÷ 2P` 枚代币按开盘价 **2P** 注入 PancakeSwap Infinity 全区间流动性，仓位由项目合约持有，**没有任何撤出路径**。卖完时进池数量正好是 90,000,000 枚。
- **定价只看内部账目**：官方池只能由 Hook 初始化，价格与数量来自创世记账，不读合约余额。外部直接转入 Hook 的资金在开盘时转给平台，推不动开盘价。
- **销毁**：未卖出的创世代币铸入黑洞地址。
- **解除限制**：同一笔交易里解除全部转账限制，代币成为普通 ERC-20。不存在"限制已解除、官方池还没建好"的间隙。

### 8.5 开盘时参与者的账面

| 参与者 | 成本 | 开盘价 2P 相对成本 |
|---|---|---|
| 第一个 | P | 2.0 倍 |
| 平均 | 1.25P | 1.6 倍 |
| 最后一个（卖完时） | 1.5P | 1.33 倍 |

### 8.6 不设软顶，也不设最低募集额

没有退款，募集多少就按多少开盘。只要有人参与过，开盘就能完成；募集很少时池子会很浅，价格波动会很大（见第 17 节）。

## 9. 持续阶梯发行

### 9.1 为什么开盘之后还要继续发行

"毕业即顶峰"的根因是一级发行在开盘时结束。ToshX 的做法是改结构：**让一级发行在二级市场存续期间继续运行，且价格逐级上行。** 价格涨得越高，解锁的新供给越多，在结构上抑制单边暴涨和随之而来的踩踏；同时，货架收入的大部分回流池子，项目方也获得一个随币价上涨持续释放的资金来源。

### 9.2 货架参数

| 参数 | 值 |
|---|---|
| 档数 `TIER_COUNT` | 10,000 |
| 每档数量 | 183,000 枚 × 募集额 ÷ 硬顶（向上取整，开盘时固定） |
| 阶梯总量 | 1,830,000,000 枚 × 募集额 ÷ 硬顶 |
| 第 0 档价格 | 开盘价（2P） |
| 每档涨幅 | 约 0.346%（$(10^{15})^{1/9999}$） |
| 首尾价差 | 10¹⁵ 倍 |
| 单笔交易最多跨越 | 32 档（约 11.7% 的价格区间） |

**没募满，货架按比例缩小。** 开盘池的代币数量是 90,000,000 × 募集额 ÷ 硬顶，所以货架也按同一比例缩小：卖完时每档 183,000 枚；只募到一半时每档 91,500 枚。这样无论募了多少，每一档相对池子深度的占比都一样（约为池子代币侧的 0.2%），小项目的第一档不会一下子砸穿浅池。每档数量在开盘那一刻算出并写死，之后不再变化。

档数多、每档小，是为了让新供给细水长流：满募时，市场每翻一倍大约打开 3,700 万枚货架，约为开池代币的 41%。

### 9.3 谁能买：Agent ID 与货架额度

货架只卖给持有 Binance Agent ID 的钱包，每个 ID 在每个项目上有终身额度 `shelfCapPerAgent`（BNB 市场 0.7 BNB，USDT 市场 500 USDT，§7.4）。没有 Agent ID 的人仍然可以在池子里自由买卖。

这样做的原因和创世一样：货架价不高于市场价，是一份实打实的好处，应该按身份分配，而不是被批量钱包或机器人全部拿走。

### 9.4 价格闸门：不高于市场价

货架第 i 档只在其价格不高于 $\min(\text{现价}, \text{TWAP})$ 时可售，即上限就是参考价本身（面值）。开盘后 30 分钟内，参考价取 $\min(\text{现价}, 2P)$，所以这段时间最多只能打开第 0 档。

- **货架永远不比市场贵。** 能买到的每一档都不高于参考价，所以只要池子价格涨过某一档，从货架买就比从池子买划算，货架因此卖得动。
- **给上涨踩刹车。** 池子价格明显高于已解锁的货架档时，持有 Agent ID 的参与者可以从货架买入、卖进池子，把价格拉回货架附近。扣除 1% 交易税和 0.2% LP 手续费后，这种套利只在池子价格高于货架价约 1.2% 以上时才有利可图，不会把价格砸到 2P 以下。套利的总量受每个 ID 的货架额度限制。
- **创世参与者不会被稀释到成本以下。** 货架最低价 2P，高于任何创世参与者的成本（P 到 1.5P）。
- **开盘区块关闭。** 开盘所在区块不允许铸币，阶梯从下一个区块开始。同一区块内池子价格变动超过约 0.1%（`MAX_MINT_TICK_DRIFT = 10` 个 tick）后，该区块也不能再铸币。

### 9.5 30 分钟 TWAP

`TWAP_WINDOW = 1800` 秒。要解锁更高的货架，价格必须真实维持半小时以上；在 TWAP 未成熟之前，参考价取 $\min(\text{现价}, \text{开盘价})$。闪电贷或单区块拉盘打不开阶梯。30 分钟是一个权衡：它让操纵者必须真实地持有被拉高的价格，同时让一个真实上涨的市场能在一小时内打开阶梯。

### 9.6 收入去向：80% 回流池子

每一笔货架付款在同一笔交易里分成三份，合约不托管其中任何一份：

| 份额 | 去向 |
|---|---|
| **80%** | `ToshAutoLp`：买入项目代币，加进项目自己的池子，永久锁定 |
| **19%** | 该项目的 Circuit 收入金库（§12） |
| **1%** | 回购金库（§11） |

`ToshAutoLp` 每种计价币一个，为每个项目单独记账。它把收到的计价币大约一半用于在项目池子里买入代币，再把买到的代币和剩下的计价币作为全区间流动性加进池子。这部分流动性和创世仓位一样，**没有任何撤出路径**；它赚到的手续费也会记回待加额度，下一次一起加进池子。

买入可能被夹子攻击，所以只在价格可信时执行，否则先挂起：

| 条件 | 值 |
|---|---|
| TWAP 已成熟 | TWAP 未满一个窗口时不执行 |
| 现价不高于 TWAP 太多 | 平方根价格偏离不超过 0.99%（`MAX_SPOT_PREMIUM_SQRT_BPS = 99`，约 2% 价格） |
| 单次规模 | 不超过池子虚拟计价币储备的 2%（`MAX_DEPTH_BPS = 200`），其中约一半用于买入，买入冲击约 1%，低于夹子往返约 2% 的成本 |
| 价格移动上限 | 单次买入最多把平方根价格推动 2%（`MAX_SWAP_SQRT_MOVE_BPS = 200`），作为兜底 |

没加进去的部分记为挂起（`pendingQuote` / `pendingToken`），在下一次货架购买时继续尝试；任何人也可以调用 `flush` 推进，但要求本区块还没有发生过 swap。挂起或失败永远不会让触发它的货架购买失败。`ToshAutoLp` 的买入和普通买入一样缴纳 1% 买入税，但不会顺带触发回购。

这样设计的结果是：**币价越高，货架卖得越多，池子就越深。** 项目方只拿 19%，自己出钱拉盘、买货架、再卖出的循环是亏钱的。

## 10. 交易与费用

### 10.1 费用一览

| 项目 | 费率 | 去向 |
|---|---|---|
| 池子手续费 | 0.20% | 流动性提供者（见 10.3） |
| 买入税 | 1.00%（按计价币输入） | 0.60% 项目方（Circuit 收入金库）+ 0.40% 回购金库 |
| 卖出税 | 1.00%（按代币输入） | **就地销毁** |
| 交易者总摩擦 | 1.20% | |
| 货架收入 | 付款的 100% | 80% 买币加池 + 19% 项目方 + 1% 回购金库 |
| 买单簿手续费 | 买卖双方各 1%，只在开盘前成交时收取 | 平台 |
| 发射费 | 无 | |

### 10.2 每一档为什么这样设

- **买入税六成归项目方。** 项目方的收入直接来自真实交易：项目越活跃，收入越多，不需要卖币。其余四成进回购金库，回购的动力同样来自真实交易，而不是平台补贴。
- **平台不从交易税里分成。** 平台在交易上的收入只有创世仓位手续费的计价币一侧（§10.3），只持有 BNB 和 USDT，对所有项目保持中立。
- **卖出税全部销毁。** 卖出侧收到的是项目代币，分给任何人都只会变成新的卖压。卖压越大，销毁越多；卖出侧天然通缩，不经过任何人的钱包。
- **不收发射费。** 降低项目方的进入门槛，让平台收入只来自真实交易量。

### 10.3 池子手续费归谁

任何人都可以为项目池添加流动性，第三方 LP 按自己的仓位赚取 0.20% 手续费，用来补偿无常损失。

**永久锁定的创世仓位**同样在赚取手续费。这部分由 `collectGenesisFees()` 结算，任何人都可以调用，去向是固定的：**计价币一侧归平台，代币一侧直接销毁**。所以创世仓位的手续费既是平台的运营收入，也是持续的通缩来源。

`ToshAutoLp` 加进池子的仓位赚到的手续费不归任何人，全部记回待加额度，继续加深池子（§9.6）。

### 10.4 示意：每 1,000 BNB 买入量

| 去向 | BNB |
|---|---|
| 项目方（Circuit 收入金库） | 6.0 |
| 进入回购金库，最终买入并销毁项目代币 | 4.0 |
| 池子手续费（归 LP；创世仓位部分的计价币归平台，ToshAutoLp 仓位部分继续加池） | 2.0 |

以上为按合约常量计算的示意，不是交易量预测；USDT 项目按同样的比例计算。

## 11. 单向回购金库

### 11.1 只进不出

`ToshLadderTreasury` 没有 `withdraw`、`sweep`、`rescue`，也没有 `delegatecall`，`renounceOwnership` 被禁用。它的唯一出口是：在名册上某个项目自己的池子里市价买入该项目代币，送到 `0xdead`。

每种计价币一个金库：BNB 项目的税收进 BNB 金库，USDT 项目的进 USDT 金库，两者互不相通。

**收入：** 买入税中的 0.40%，以及货架付款的 1%。

### 11.2 回购如何执行

| 参数 | 值 | 为什么 |
|---|---|---|
| 触发阈值 `TRIGGER_STEP` | BNB 金库 0.3 BNB；USDT 金库 180 USDT | 每个金库部署时写死，之后不可改。两者价值大致相当：再低，钱会被 gas 吃掉；再高，钱会闲置 |
| 每轮花费 `SPEND_BPS` | 余额的 50%，至少一个触发阈值 | 买盘持续释放，而不是一次砸光 |
| 分配方式 `BATCH_SIZE` | 每轮固定三等分 | 名册只剩一个币也只拿 1/3 的速度，防止集中 |
| 每次执行 `LEGS_PER_POKE` | 1 笔 | 触发交易的用户多付的 gas 只有原来的三分之一 |
| 单笔上限 `MAX_LEG_DEPTH_BPS` | 池子深度的 0.5% | 让夹子攻击无利可图（见下） |
| 价格带 `MAX_BUYBACK_SQRT_DEVIATION_BPS` | 平方根价格偏离 TWAP 10%（约 19% 价格） | 单轮回购不能把价格推得太远 |

回购由普通交易自动触发：每笔 swap 结束时，如果金库余额已到阈值，就顺带执行一笔回购（`ToshAutoLp` 的买入除外）。它不依赖平台或机器人，任何人也可以调用 `pokeBuyback()` 手动推进。

### 11.3 为什么单笔不超过池深 0.5%

夹子攻击回购的盈亏，只取决于"单笔回购 ÷ 池子深度"这一个比值：攻击者的收益约为（单笔 / 深度）× 拉盘资金，成本是往返两次的摩擦（0.2% 池费 + 1% 税，约 1.2%）。两者都与拉盘资金成正比，资金规模被约掉，所以**只要单笔/深度低于约 1.2%，夹子就必亏**。`test_F2_stackedPokesSandwichDoesNotPay` 和 `test_F2b_flashSandwichInOneLockDoesNotPay` 持续验证夹子不赚钱。0.5% 留出约 2.4 倍余量，用来吸收模型没有覆盖的曲率、免税腿和区块构建者自己做夹子的情形。

代价是薄池子的回购会被切成更小的份额——这是正确的行为：一笔占了池子三分之一的回购，买到的大部分是它自己造成的滑点。

### 11.4 名册由谁决定

金库的保管权没有任何人能碰，但"买哪些币"由名册决定。代币需要先通过 30 分钟 TWAP 成熟检查，才能由平台多签加入名册（`addLadderToken`），以杜绝用闪电贷抬高瞬时价格再套利回购。固定三等分和 TWAP 价格带让治理方无法把整个金库集中砸向某一个币；名册的增删本身置于与其他经济参数同级的多签评审之下。

## 12. Circuit NFT：项目方的长期收入

每个项目上架时，工厂会给开发者铸造一枚 **Circuit NFT**，并部署一个与之绑定的 `CircuitRevenueVault`（收入金库）。

### 12.1 收入从哪里来

- 货架付款的 **19%**；
- 每笔买入税中的 **0.60%**（按计价币输入计）。

两者都按合约固定地流入金库，平台无法截留或改道。此外，NFT 持有者还控制该项目的项目基金（20% 募集资金，§8.2），可以随时提到 `projectFund` 地址。

### 12.2 谁能取

持有 Circuit NFT 的地址可以随时从金库提取，没有延迟。金库没有通用的 `execute`，只能收款和付款，因此持有者不能借它的身份去调用项目合约。Circuit NFT **不带任何对项目代币、池子或 Hook 的控制权**——它只是一份收入权。

### 12.3 收入权可以转让

Circuit NFT 是标准 ERC-721，可以转让或出售。每次转让时，合约会依次：

1. 把收入金库里的全部余额付给卖方；
2. 把项目基金里已记账、还没提取的 20% 募集资金，付到当前的 `projectFund` 地址；
3. 把 `projectFund` 改为买方地址。

所以**卖出 Circuit 只卖出未来的收入**：转让之前赚的钱属于卖方，买方从空金库、空基金开始，之后的项目基金也直接归买方，买之前不需要做任何核查。

### 12.4 这让激励对齐了什么

项目方的收入不来自一次性募资，而来自"交易活跃带来的买入税"和"币价上涨带来的货架销售"。**想拿更多钱，只能把项目做好**——这正是持有人希望项目方做的事。而货架收入的大头（80%）回到池子里，项目方无法靠自己买货架来套现。

## 13. 服务两类创业者：加密项目与 Web2 小企业

### 13.1 加密项目（已上线）

新代币、社区项目、链上应用可以直接使用全部机制：Agent ID 公平首发、零预挖、开盘即有永久流动性、随币价持续加深的池子、随交易与币价释放的持续资金、写在合约里的回购销毁。

### 13.2 Web2 小企业（规划）

> 本节描述的是方向，而非已上线的功能。

独立品牌、小店、工作室、内容创作者今天的融资选项非常有限。ToshX 的机制对他们同样适用：

| 传统渠道的问题 | 在 ToshX 上 |
|---|---|
| 银行要抵押、要流水 | 不需要抵押，凭项目本身通过审核 |
| VC 只看少数赛道 | 任何认真做事的团队都可以申请 |
| 众筹抽成高、规则不透明 | 不收发射费，所有费用写在合约里 |
| 支持者的回报无法流通 | 支持者获得的社区代币可以随时在池子里交易 |
| 募来的钱去向不透明 | 80% 永久锁进池子、20% 进项目基金，比例写在合约里，每一笔都能在链上查到 |
| 一次融资之后再无资金 | 业务成长带来的交易和需求，通过买入税和阶梯发行转化为持续融资 |

我们会先以试点方式推进，在符合当地法规与合规要求的前提下逐步开放。需要明确的是：**项目代币是社区代币，不是股权**，不代表对企业资产或利润的任何法律权利。如何在合规框架内把链上社区与线下业务连接起来，是我们下一阶段要和合作方一起回答的问题。

## 14. 治理、权限与紧急制动

### 14.1 权限结构

每种计价币一个工厂，每个工厂的所有者是各自的**发射网关** `ToshLaunchGateway`，网关背后是同一个 **2-of-3 Safe 多签**；两个回购金库直接归这个 Safe 所有。`ToshAutoLp` 没有所有者：它在部署时绑定工厂，之后没有任何管理函数。

- Safe 的任一签名人可以通过网关**上架项目**；从 Safe 移除签名人的同一笔交易里，他的上架权限即被收回。开盘不需要任何平台权限（§8.4）。
- 其余所有管理权限只能由 Safe 本身通过 `execute` 调用，需要 2-of-3 签名。
- 工厂和金库的 `renounceOwnership` 都被禁用：所有权可以转移，但不能被放弃——"没有管理员"比"管理员是一个选择不行动的多签"更糟，因为那会同时丢掉所有紧急制动。

### 14.2 平台能做什么、不能做什么

| 平台**能**做 | 平台**不能**做 |
|---|---|
| 审核并上架项目 | 动用任何人的代币、买单簿托管资金、项目基金或 `ToshAutoLp` 的待加资金 |
| 调整**新项目**硬顶与 Agent ID 额度的允许范围 | 撤出任何项目的创世流动性或 `ToshAutoLp` 加进去的流动性 |
| 调整每个 Agent ID 的货架额度（对所有项目同时生效） | 从回购金库提走任何资金 |
| 暂停某个项目或全部项目的**创世买入** | 改变平台收款地址（工厂与 Hook 中均为 immutable） |
| 屏蔽个别地址的创世买入（可设期限） | 修改已上架项目的价格曲线、创世额度、资金分配和开盘规则，或升级任何合约 |
| 暂停货架铸币（最长 7 天） | 阻止开盘、转账、撤单和买单簿成交 |
| 增删回购名册；收回误上架项目的名称 | |

### 14.3 紧急制动及其边界

| 制动 | 作用范围 | 不影响 | 期限 |
|---|---|---|---|
| `pause()` | 新项目上架 | 已上架项目的一切 | 直到解除 |
| `setGenesisPaused` | 指定项目（或全部）的创世买入 | 已买到的代币、转账、买单簿、开盘 | 直到解除；最坏结果是募资偏小，照常开盘 |
| `setBlacklist` | 指定地址的创世买入 | 该地址已持有的代币、转账、买单簿 | 按设定期限，或直到解除 |
| `haltLadderMinting` | 指定项目（或全部）的货架铸币 | 交易、LP、开盘、买单簿 | **最长 7 天自动失效**，续期必须在链上公开进行 |

设计原则只有一条：**刹车只能阻止"新增"，不能扣住任何人已经投入的资金。** 被屏蔽的地址依然可以转出和卖出已有的代币；暂停中的平台依然无法阻止任何项目开盘，也无法阻止任何人卖出。

## 15. 安全与验证

- **测试。** v3 合约测试共 443 项，覆盖单元、模糊、不变量和 BSC 主网分叉测试，CI 对测试数量设下限。
- **持续验证的不变量。**
  - `invariant_supplyIsAccountedFor`：开盘前总量等于创世已卖出量，开盘后等于 2.7 亿加上货架已铸出量；
  - `invariant_genesisStaysInsideItsCaps`：募集额不超过硬顶，每个 Agent ID 的花费不超过额度；
  - `invariant_hookHoldsExactlyWhatItOwes`：开盘前 Hook 里正好是全部募集额，开盘后只剩未提取的项目基金；
  - `invariant_noTokenReachesAContractBeforeLaunch`：开盘前代币到不了任何池子或路由合约；
  - `invariant_escrowPlusFeesEqualsBalance`：买单簿的余额始终等于托管加未提手续费；
  - `invariant_buybackFlagNeverLeaks`：回购的内部状态不会泄漏到下一笔交易。
- **攻击测试。** 包括夹子攻击回购、JIT 流动性绕过深度上限、TWAP 操纵、开盘前绕过转账限制、项目方自买货架套现（`test_H1_controllerSelfFundedCycles_loseMoney`），以及 `ToshAutoLp` 在 TWAP 未成熟、现价偏高、单次超限时的挂起行为，结果以测试形式固定在代码库中。
- **溢出余量。** 总量放大到 21 亿后，曲线计算的中间值约 10⁵⁵，远低于 uint256 上限；货架记账字段和价格 tick 均在类型范围之内，已逐项核对。
- **静态分析。** CI 对 Slither、Aderyn、forge lint 设置基线门禁，每一条发现都有书面处置（`docs/AUDIT.md`）。
- **源码公开验证。** v3 的 18 个主网合约（含两个工厂部署时创建的代币、Circuit NFT 和收入金库实现合约）已在 Sourcify 完全匹配（exact match），创建字节码和运行时字节码均一致；v2 的 16 个合约同样已完全匹配。BscScan 验证在路线图中（§16）。
- **运行监控。** 链上事件与关键状态定时比对。例如所有权是否仍在 Safe 手中、买单簿余额是否覆盖全部托管，会被逐项检查。
- **不可升级。** 项目代币、Hook 和 Circuit 收入金库均为最小代理克隆，实现合约地址写死在克隆体的字节码里；工厂中的实现地址也是 immutable、没有 setter；买单簿和 `ToshAutoLp` 没有管理员。整个系统没有任何升级路径。

## 17. 已知局限

一份不写局限的白皮书不值得据以决策。

1. **第三方审计尚未完成。** 已列为近期第一优先级。
2. **准入依赖第三方注册表。** Agent ID 注册表由 SPACE ID / Binance 管理，其管理员可以直接发放 ID。一个 Binance 账户只能领一个 ID，但账户本身可能被买卖，所以"一个 ID 一份额度"不等于"一人一份"。
3. **参与依赖 Binance 的钱包产品。** 首发和货架都要用 Agentic Wallet 的开发者模式完成，受 Binance 的地区服务范围、风控规则、开发者模式每日额度（1,000 – 50,000 USDT）和余额上限约束，这些都不在协议控制之内。没有 Binance 账户的用户不能参与首发和货架，但可以在买单簿和池子里买入。
4. **单链依赖。** 协议运行在 BSC 与 PancakeSwap Infinity 之上，继承它们的可用性与安全假设。
5. **回购名册是治理面。** 保管权无人能碰，但"买哪些币"由多签决定；代码对集中度做了限速，但无法替代治理本身。
6. **上架是审核制。** 这是为了保护参与者做出的取舍，代价是上架速度取决于平台的审核能力。
7. **Web2 方向尚在规划。** 涉及的合规问题需要在试点中逐步解决。
8. **没有退款。** 买入即最终成交，开盘后价格可能跌破成本。
9. **开盘前只挡链上价格发现。** 链下 OTC 挡不住；两个 7702 账户之间还可以在一笔交易里原子地完成私下成交。合约钱包（Safe 等）开盘前不能参与首发，也不能转出代币。
10. **买单簿成交价可能低于开盘价。** 成交价最低为最新参与价的 90%，卖完后约在 1.35P 到买家出价之间，而开盘价是 2P。只靠自买自卖、付 2% 手续费就能刷出成交价，页面同时显示成交量。
11. **开盘抛压。** 卖完时参与者手里有 180,000,000 枚，池子里只有 90,000,000 枚；开盘时人人账面盈利，集中卖出可能让池子价格大幅下跌。
12. **货架持续带来新供给。** 满募时市场每翻一倍，货架约放出 3,700 万枚，约为开池代币的 41%；池子很难脉冲式上涨。
13. **货架刹车的力度有限。** 只有持 Agent ID 的钱包能在额度内买货架，所以把池子价格拉回货架附近的套利总量有上限；行情过热时，池子价格可能在一段时间内明显高于已解锁的货架。
14. **加池可能延后。** 行情剧烈波动、TWAP 未成熟或池子太浅时，`ToshAutoLp` 会把货架收入挂起，等价格平稳后再加进池子；挂起期间这部分资金暂时不在池子里，但也不属于任何人。
15. **开盘后可能出现第三方池子。** 任何人都可以用其他 Hook 或不用 Hook 另建池子；官方池以永久锁定的深度和官方 PoolId 标识为准，偏离的价格会被套利拉回。
16. **项目基金由项目方支配。** 20% 募集资金由 NFT 持有者提取和使用，收款地址可以随时修改，平台不做监管。NFT 转让时，未提取的部分付给转让前的收款地址，之后改为买方。

## 19. 结语

ToshX 的主张都可以在链上核验，而不必相信任何人的承诺：

- **额度由 Binance Agent ID 决定**，创世和货架都是一个 ID 一份，不由白名单、关系或机器人速度决定；
- **价格只看卖出了多少**，从 P 线性涨到 1.5P，开盘价 2P，流动性永久锁定；
- **一级发行不在开盘时结束**，货架收入的 80% 回流池子，项目方的收入与交易和币价同向；
- **平台收入的去向写死在合约里**，回购金库没有提款口。

我们还很小。但我们想让 Web3 变得更好：让每一个人都有机会公平参与，让每一个认真做事的创业者——无论在链上还是链下——都能拿到属于自己的那笔融资。
