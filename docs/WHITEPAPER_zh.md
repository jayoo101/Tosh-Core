## 摘要

Tosh 是一个**端到端以 ETH 计价**的公平发射协议。每个项目拥有自己的 Uniswap V4 Hook：创世募资、真池创建、一级货架发售、换手税与回购销毁，全部发生在同一套链上规则里。

它与常见发射台的三个结构性差异是：

1. **池子先于二级市场存在。** 募资结束的那一刻创建 Uniswap V4 真池。分级货架是与池并行的一级发行通道，并且反过来受池子自己的价格约束——不是“曲线里交易、毕业后才建池”。
2. **没有团队预挖。** `launch()` 只铸造 840 万枚创世供应；剩余 1,260 万枚在货架被买走时按需铸造。浏览器上不会出现一个持有 100% 供应量的地址。
3. **平台金库是单向阀。** `ToshLadderTreasury` 没有 `withdraw`、`sweep`、`rescue`，也没有 `delegatecall`。它唯一的对外支出路径把代币送到 `0xdead`。所有者可以调参、暂停、拉黑，但**不能转移任何人的一个 wei**。

创世存款人的开盘账面溢价是 **恰好 10%**：它不是写死的目标价，而是 55/45 供应拆分与 10% 返佣提成共同决定的算术后果。货架第 0 层再叠 5%，相对存款成本为 15.5%。

交易者的总摩擦是 **1.30%**：0.30% 归流动性提供者，1.00% 为协议税。买入侧协议税拆成 70 bps 回购燃料与 30 bps 平台维护收入；卖出侧 1.00% 代币就地烧毁，平台不分成。

## 1. 它解决什么

发射台反复出现的失败模式，写在 `ToshLaunchpadHook` 与 `ToshFactory` 的源码注释里。用协议语言重述如下。

**入场必须先买平台币。** 这既是摩擦，也把所有参与者暴露在平台币运营方的风险下。Tosh 的发射费、创世存款、货架铸造、回购弹药与退款全部是原生 ETH。工厂不再存储任何平台币地址。

**团队持有大额预挖。** 按需铸造：发射只铸创世块，货架售出时才铸剩余供应。

**团队从曲线便宜一端铸币再砸回池子。** 三层价格闸门：同区块铸造禁令、`min(现价, TWAP)` 参考价、105% 上限。Phase 2 在发射当块完全关闭——由 `launch()` 自己盖上 `lastSwapBlock`，而不是靠边界算术碰巧成立。

**创世参与者在池子打开的瞬间浮亏。** 55/45 拆分使开盘价相对存款成本基准恰好为 1.10。

**池子被永久锁死，散户不敢做 LP，手续费堆在没人能领的仓位里。** 创世仓位因“仓位归 Hook 所有、且 Hook 没有移除流动性的代码路径”而锁定。第三方 LP 自由进出。`BEFORE_REMOVE_LIQUIDITY` 已从 Hook 地址掩码中移除。

**通缩依赖链下机器人。** 回购发生在 Tosh 池 `afterSwap` 的余量 gas 里，无需链下组件。不保证每笔交易都带一次回购；兜底是无需许可的 `pokeBuyback()`。

**平台金库可被所有者抽干。** 金库是单向阀，见第 8 节。

## 2. 设计原则

1. **ETH 原生。** 协议不引入第二套计价资产。gas、发射费、存款、货架、回购与退款使用同一种单位。
2. **规则在部署时冻结。** 每个项目的 Hook 以 EIP-1167 克隆部署，关键参数是 immutable。改规则等于重新部署平台，而不是给已有项目打补丁。
3. **算术比口号优先。** 10% 开盘溢价由三个可检验的数共同决定。改 55、45 或返佣率，测试 `test_genesisPremium_isExactlyTenPercent` 会失败。
4. **所有者能运营，不能挪用。** 权限清单见第 9 节。能调的旋钮都有上限；不能动的钱没有后门。
5. **失败路径是完整路径。** 软顶未达成，或募资成功但 7 天内无人调用 `launch()`，存款人 100% 无罚金退款。暂停不能扣住退款或已实现收益。

## 3. 系统结构

平台在每条链上只有两个单例，每个项目再有一对克隆。

```
ToshFactory  ──────────────►  ToshLadderTreasury
  创建发射 / PoG / 存款网关        单向阀 / 回购引擎
  返佣图 / 暂停 / 黑名单            唯一出金 → 0xdead
         │
         │ CREATE2 · EIP-1167（121 字节）
         ▼
ToshLaunchpadHook（每项目一个） ──► Uniswap V4 PoolManager
  Phase 1  存款 / 退款 / 发射            ETH / 项目代币 真池
  Phase 2  货架铸造 / 创世领取
  回调     beforeSwap / afterSwap
         │ mint（唯一 MINTER_ROLE）
         ▼
ToshToken（每项目一个）
  硬顶 21,000,000
  DEFAULT_ADMIN_ROLE 永不授予任何人
```

| 合约 | 数量 | 职责 |
|---|---|---|
| `ToshFactory` | 每链一个 | `createLaunch`、`registerPoG`、创世存款网关、终身与项目返佣图、黑名单 / 冷却 / 暂停 |
| `ToshLadderTreasury` | 每链一个 | 接收发射费、孤儿返佣、货架 1% 与买入侧 70 bps；策展回购名单；`autoPiggybackBuyback` / `pokeBuyback` |
| `ToshLaunchpadHook` | 每项目一个 | 该项目的完整生命周期与 V4 回调 |
| `ToshToken` | 每项目一个 | ERC-20；每次 `mint` 检查硬顶；铸币权只属于对应 Hook |

Uniswap V4 的 `PoolManager` 不由本协议部署。现行主网地址见附录 A。

## 4. 生命周期

```
Phase 1 · 创世募资                 Phase 2 · 池与货架并行              Phase 3 · 通缩
─────────────────────              ────────────────────────           ──────────────
合格钱包存入 ETH                   launch() 一次完成：                 买入：1% ETH 税
  10% 返佣提成                       铸 840 万创世供应                   70 bps → 金库
  90% 进入 lpEth                     建 V4 全区间仓位                   30 bps → 平台
软顶未达 → 100% 退款                 锁定创世流动性                     卖出：1% 代币 → 0xdead
7 日窗口过期 → 100% 退款             打开 4000 层货架                   金库 → 买回并烧毁
                                   货架受池价反向约束
```

### 4.1 Phase 1 · 创世募资

创建者支付发射费，选择三种时长之一：

| 常量 | 时长 |
|---|---|
| `DURATION_FAST` | 3 小时 |
| `DURATION_STANDARD` | 24 小时 |
| `DURATION_SLOW` | 72 小时 |

软顶由工厂的 `defaultSoftCap` 在创建时写入 Hook，生产环境下限为 `MIN_SOFT_CAP_PROD` = 0.01 ETH。所有者可以提高默认软顶，不能把它降到该下限之下。

存款不直接打到 Hook。工厂负责资格（PoG 配额、冷却、黑名单），Hook 负责账本（谁存了多少、返佣如何计提）。每钱包上限在创建时快照自 `maxPogAllocationLimit`。

**两条下行保护，都是 100% 无罚金退款：**

- 募资结束时 `totalEthDeposited < softCap()`；
- 软顶已达成，但 `genesisDeadline + LAUNCH_WINDOW`（7 天）之内无人调用 `launch()`。

第二条意味着“项目方拿了钱不发射”不是一个能把资金困住的状态。存款人调用 `refund()` 取回自己的本金。

### 4.2 Phase 2 · 池与货架

只有创建者可以调用 `launch()`，且必须同时满足：创世窗口已结束、软顶已达成、7 日发射窗口未过期、尚未发射。

`launch()` 按以下顺序执行，中间没有可由所有者插入的步骤：

1. 从募集总额中扣除返佣准备金（含孤儿返佣），得到 `lpEth`。
2. `p0 = lpEth / GENESIS_LP_SUPPLY`，`shelfP0 = p0 × 1.05`。
3. 向 Hook 铸造 `GENESIS_SUPPLY`（840 万）。
4. 初始化 Uniswap V4 池，注入全区间流动性（tick ±887,200，费率 0.30%，spacing 200）。
5. 盖上同块锁，使发射当块无法购买货架。
6. 若有孤儿返佣，全额转给金库。

45% 的创世供应（378 万）进入池子。55%（462 万）留在 Hook 中，供存款人按出资比例领取。领取发生在发射之后，调用 `claimGenesis()`。

**货架不是连续曲线。** v4.x 的 `tan(z)` 泰勒展开已被删除。Phase 2 是 4000 个离散定价货架：

| 常量 | 值 |
|---|---|
| `TIER_COUNT` | 4000 |
| `TIER_SIZE` | 3,150 枚 |
| `BONDING_MAX` | 12,600,000（恰好 4000 × 3,150） |
| `TIER_STEP` | 1.001902508266805824（层间 +0.19025%） |
| 端到端跨度 | 2000× |
| `MAX_TIERS_PER_TX` | 32 |

价格用快速幂闭式求值，避免 4000 次连乘的截断漂移。

货架第 *i* 层可售的条件是：

```
shelfP0 × STEP^i  ≤  min(现价, TWAP) × 1.05
```

`SHELF_PREMIUM_BPS` 与 `PRICE_CEILING_BPS` 被刻意设为同一个 10500。两侧的 1.05 相互抵消，条件塌缩为不含魔数的比较。改动其中任何一个，这个抵消就会重新长出一个系数。

货架收入的 99% 归 `projectAdmin`，1%（`PLATFORM_TAX_BPS`）进入金库。货架铸造不经过池子，与换手税作用于不同的 wei。

### 4.3 Phase 3 · 通缩

金库余额跨过 `TRIGGER_STEP` = 1 ETH 时，一笔 Tosh 池交易的 `afterSwap` 可以顺手买回并烧毁。单次支出为 `max(1 ETH, 余额的 10%)`，再除以 `BATCH_SIZE` = 3 分摊到策展名单上的代币；每次 poke 走 `LEGS_PER_POKE` = 1 条腿。滑点保护为 `MAX_BUYBACK_SQRT_DEVIATION_BPS` = 1000（相对 TWAP 的 10%）。

这套路径依赖交易的余量 gas（`PIGGYBACK_MIN_GAS` = 260,000）。gas 不够时交易本身仍然成功，回购被跳过。任何人都可以调用 `pokeBuyback()` 补上这一步。协议不保证通缩的节奏，只保证通缩的去向是 `0xdead`。

## 5. 代币经济学

每个项目的代币是独立的 ERC-20，硬顶相同，铸币权隔离。

### 5.1 供应

| 层次 | 常量 | 数量 | 占硬顶 |
|---|---|---|---|
| 硬顶 | `MAX_SUPPLY` | 21,000,000 | 100% |
| 创世供应 | `GENESIS_SUPPLY` | 8,400,000 | 40% |
| ├ 存款人领取 | `GENESIS_CLAIM_SUPPLY` | 4,620,000 | 22%（创世的 55%） |
| └ 创世流动性 | `GENESIS_LP_SUPPLY` | 3,780,000 | 18%（创世的 45%） |
| 货架 | `BONDING_MAX` | 12,600,000 | 60% |

8,400,000 + 12,600,000 = 21,000,000。货架全部售出时，供应落在硬顶上，而不是逼近硬顶。

`DEFAULT_ADMIN_ROLE` 永不授予任何人。Hook 是唯一持有 `MINTER_ROLE` 的地址。没有人能再授予或撤销该角色。

### 5.2 开盘溢价的来源

记募集总额为 *R*。进入池子的是 `0.9R`（无论这 10% 最终付给推荐人还是金库）。

```
存款人成本基准   P_raise = R / 4,620,000
池子开盘价       p0      = 0.9R / 3,780,000

p0 / P_raise = (0.9 / 3,780,000) × 4,620,000
             = 0.9 × (4,620,000 / 3,780,000)
             = 0.9 × 1.222… 
             = 1.10
```

**1.10 由三个数共同决定：55、45、以及 10% 的返佣提成。** 动其中任何一个，溢价就变。货架第 0 层定在 `p0 × 1.05`，相对成本基准为 1.155，因此一级发售不会从下方切存款人。

这不是被写死的目标价。测试钉的是这个关系，不是一个硬编码价格。

### 5.3 40/60 拆分实际抑制了多少早期卖压

货架在市价达到开盘价的 *R* 倍时，已释放的 Phase-2 比例只取决于跨度，与 Phase-2 总量无关。要减少上涨途中砸向市场的**绝对代币数**，只能缩小货架本身。

在 2× 价位：

| 配置 | 释放枚数 | 相对创世供应 | 相对可流通创世（4.62M） |
|---|---|---|---|
| 20/80 + 2000× | 1,533,000 | 36.5% | 33.2% |
| **40/60 + 2000×（现行）** | **1,149,750** | **13.7%** | **24.9%** |

13.7% 这个分母含有永久锁在创世仓位里的 378 万枚——它存在，但永不进入交易。换成会实际交易的流通量，两倍价位上市场需消化约四分之一的活跃供应。

上表同时列出三个分母，因为它们回答的是不同问题：比较三种配置的优劣看第三列（同一基准下 36.5% → 13.7%），估算市场实际承压看第四列。跨度与拆分都是参数，取舍记在附录 D。

## 6. 费用

| 收费点 | 费率 | 去向 |
|---|---|---|
| Uniswap V4 池费 | 0.30% | 该仓位的 LP，由 V4 原生结算 |
| 换手税 · 买入 | 1.00% ETH | 70 bps → 金库（回购）；30 bps → `platformFeeRecipient`（平台维护） |
| 换手税 · 卖出 | 1.00% 代币 | 全额 → `0xdead`，就地烧毁 |
| 货架分成 | 1% ETH | → 金库；其余 99% → `projectAdmin` |
| 发射费 | 现行 0.01 ETH | → 金库 |
| 孤儿返佣 | 该笔存款的 10% | `launch()` 时 → 金库 |

交易者看到的总摩擦是 **1.30%**。

`TAX_BPS` = 100 与 `PLATFORM_TAX_BPS` = 100 数值相同、基数不同：前者是换手输入的 1%，后者是货架收入的 1%。两者永不作用于同一个 wei。

**必须写明的信任让步。** 更早的表述是“四条管道全部流入金库，唯一用途是买回并烧毁”。这句话现在是假的。买入侧 30 bps 归平台，不回购、不烧毁，是可自由支配的收入。到达回购引擎的绝对金额仍是买入的 70 bps；变的是交易者总摩擦从 1.00% 升到 1.30%——多出的 30 bps 是新增的，不是从回购里挪出来的。`platformFeeRecipient` 是 immutable，改它必须重新部署工厂。

## 7. 返佣

每笔创世存款计提 **恰好 10%**（`REFERRAL_BPS` = 1000）。这 10% 是开盘溢价能成为结构常数的前提：从池子看，有没有推荐人都只有 90% 进池。

同一笔 10% 在两个槽位之间拆分，不是再加一层：

| 槽位 | 份额 | 绑定范围 |
|---|---|---|
| 项目推荐人 | 存款的 8% | 每个钱包在每个项目上绑定一次 |
| 终身推荐人 | 存款的 2% | 每个钱包在全平台绑定一次，永久 |

`deposit` 只接收一个推荐人参数，同时尝试写入两个槽。空槽才接受；已写入的槽静默忽略新值。过期链接因此不会让存款失败。自荐被工厂忽略。

任一空槽对应的那一腿在 `launch()` 时进入金库，成为回购弹药，而不是变成死在 Hook 里的 ETH。

佣金在存款时计提，在 `launch()` 之后才可领取。失败的创世全额退还存款人，永不支付佣金。领取按项目进行：每个 Hook 持有自己的准备金，调用自己的 `claimReferralReward()`。不存在一个跨项目的平台资金池。

推荐人需要自己的 Proof-of-Gas 证明，两个槽才会绑定。项目槽还有第二条门：推荐人须已在该项目有过存款。两条都不满足时，存款仍然成功，对应的提成进入金库。

## 8. 金库与流动性

### 8.1 单向阀

`ToshLadderTreasury` 的入金来自发射费、孤儿返佣、货架 1% 与买入侧 70 bps。出金只有 `_buyAndBurn`：在策展名单上的 Tosh 池里买入，代币送到 `0xdead`。

没有 `withdraw`。没有 `sweep`。没有 `rescue`。没有 `delegatecall`。所有者可以决定**哪些代币**进入回购轮转，不能决定钱去向何处。

### 8.2 创世流动性与散户 LP

V4 把仓位键到创建者。创世仓位属于 Hook，Hook 没有 `modifyLiquidity` 的移除路径。锁定来自所有权结构，不来自一个可以被改掉的回调。

第三方使用自己的仓位，可以随时加入和退出。0.30% 池费归这些仓位，由 V4 结算，不经过本协议的会计。

## 9. 资格：Proof-of-Gas

创世存款不是对每个新地址开放的。配额由链下扫描与链上校验共同决定。

服务端汇总申领地址在 Ethereum、Arbitrum、Optimism、Base、Robinhood 上的历史 gas 支出。低于 `POG_GAS_FLOOR_WEI` = 0.05 ETH 的地址被拒绝。通过则按实时汇率折算 `maxAlloc`，再受链上 `maxPogAllocationLimit()`（现行 0.1 ETH）约束。

配额以 EIP-191 签名下发。摘要为：

```
keccak256(abi.encode(sender, maxAlloc, nonce, deadline, factory, chainId))
```

六个字段全部签入。工厂用 `address(this)` 参与哈希，指向其他工厂的签名在此无法恢复。`registerPoG` 校验签名者、期限与 nonce。

这把“每个新地址都是一份新配额”的成本，锚定到攻击者在主流链上已经烧掉的 gas——一段无法凭空生成的历史。

PoG 扫描依赖 Blockscout 的 keyed API，有日额度上限。额度耗尽时，创世申领对所有人关闭。这是协议自己承认的可用性风险，不是被忽略的运维细节。

汇率 `globalGasToSatoRate` 存在链下。工厂所有者是 Gnosis Safe 时，轮换走 ERC-1271，而不是浏览器里的 ECDSA。

## 10. 治理边界

现行所有者是 Gnosis Safe `0x2953957774482efA660921df85A1E7634ccfe27A`（2-of-3）。工厂与金库均使用 `Ownable2Step`：转移所有权需要接收方主动 `acceptOwnership()`。

**所有者可以：**

- 调整发射费（上限 `MAX_LAUNCH_FEE` = 10 ETH，允许为 0）；
- 调整默认软顶（下限 `MIN_SOFT_CAP_PROD` = 0.01 ETH）；
- 调整 PoG 配额上限、冷却时长（上限 `MAX_COOLDOWN` = 7 天）；
- 黑名单、暂停工厂的 `createLaunch` 与 `registerPoG`；
- 策展金库的回购名单；
- 暂停某个或全部项目的货架铸造，每次不超过 `MAX_HALT_DURATION` = 7 天，到期自动解除。

**所有者不可以：**

- 转移金库或任何 Hook 里属于存款人、推荐人或 LP 的资金；
- 改 `platformFeeRecipient`（immutable）；
- 移除创世流动性；
- 用阶梯暂停扣住退款、创世领取或返佣领取。

`pause()` 不关闭已经开始的创世存款。已经在进行的募资继续收款。货架暂停可以让买家错过一档价格，不能让任何人损失已经入账的余额。

治理不是“无治理”。边界是实的，权限也是实的。

## 11. 安全姿态

尚未进行第三方审计。以下是不依赖审计、任何人都能独立核验的事实。

- 五个合约在 Blockscout 上为 `partial match`：运行时字节码一致，差异在尾部 metadata 哈希。
- 部署 tag `deploy-4663-2026-09-12` 固定了对应提交。`HOOK_CREATION_CODEHASH` 经 `RecomputeInitcodeHash` 复核。

- 仓库保留一份持续更新的 `SECURITY_AUDIT.md`。它记录的是被发现并关闭的缺陷，包括文档与行为不一致、部署后监控盯错合约、以及只能在真实主网请求上暴露的路径。它不是营销材料。

## 12. 结语

Tosh 把发射拆成三件可以分别核验的事：募资是否有退路、开盘价是否由已知算术给出、以及平台是否有能力拿走不属于它的钱。

第一件由软顶与 7 日僵尸窗口回答。第二件由 55/45 与 10% 提成回答。第三件由金库没有出金后门、创世仓位没有移除路径、以及平台费收款地址不可变来回答。

其余的——货架节奏、回购是否赶上每一笔交易、PoG 扫描是否一直在线——是运营与参数，不是信任假设。它们连同其他设计取舍一并列在附录 D，每条都指回给出机制细节的小节。

## 附录 D · 设计权衡与已知边界

正文各处提到的设计取舍集中在这里，便于一并核对。每条都指回给出机制细节的小节，并在同一行给出对应的约束或兜底机制。

1. **运行记录自 2026-09-12 起。** 本文对机制的描述来自源码与测试套件，不是历史统计。读到任何“因此会如何”的推断时，应按设计命题理解。
2. **早期货架释放量。** 见 §5.3：2× 价位释放 1,149,750 枚，占活跃流通约四分之一。跨度（2000×）与 40/60 拆分都是参数，不是常量。
3. **搭便车回购由 gas 余量决定，不保证每笔交易都触发。** 见 §4.3。无人 `poke` 且每笔交易 gas 都紧时，金库会积压 ETH。`pokeBuyback()` 是无权限的兜底入口，任何人可调用；`monitoring/alerts.json` 的 `STATE-06` 专门监控“已武装但静默”这一状态。
4. **买入侧 1.00% 税中，70 bps 进入回购销毁，30 bps 为平台运营收入。** 见 §6。这 30 bps 是唯一不承诺销毁的费用；收款地址为 immutable 且无 setter，改向需要重新部署整个工厂。卖出侧不分成，1.00% 全额就地烧毁。
5. **PoG 资格依赖链下扫描服务。** 见 §9。配额窗口耗尽会在平台范围内暂时拒绝新的资格注册；已发放的额度、已完成的存款与退款路径都不受影响。
6. **单链部署。** 继承 Robinhood Chain 的活性、最终性与去中心化程度。该链主网于 2026 年 7 月上线。
7. **源码验证为 partial match，不是 exact match。** 见 §11：运行时字节码逐字节一致，差异仅在其后的 metadata 哈希，该段不含可执行指令。Sourcify 与 Blockscout 各自独立编译比对，结论一致。
8. **治理为 2-of-3 多签，不是销毁密钥。** §10 列出的旋钮仍然可调用，同节也列出了它们碰不到的东西。其中不含任何出金路径：金库没有 `withdraw`、`sweep` 或 `rescue`，ETH 只能经买入销毁流向 `0xdead`。
9. **目录元数据存放在链下。** logo、描述与社交链接存在注册表中，由创建者签名授权写入。链上流程不依赖它们：缺一行不会阻止 `launch()`、存款、领取或交易，只影响目录展示与推荐短链的落地页。
