## 1. 平台定位与设计原则

**定位**：ToshX 是**审核制**发射平台，类似 IDO 平台。每个项目都经过平台审核、由多签上链，用户看到的都是已经审核通过的项目。

**设计原则**

1. **阶段驱动**：同一个项目页，按"预热 → 创世中 → 待开盘 → 交易中"自动切换主面板。用户永远只看到当前能做的事。
2. **资格先行**：连接钱包后的第一件事，是告诉用户"你能不能参与、能买多少"。
3. **价格透明**：P、当前价、1.5P、开盘价 2P 全程可见，让用户知道自己在曲线的哪个位置。
4. **风险显式**：没有退款、开盘前转账限制、买单簿价格风险等关键规则，都要在用户操作前明确展示并要求勾选确认。
5. **两种操作方式并存**：网页钱包直连，以及给 AI agent 执行的"Agent 模式"（见 §4.3）。
6. **沿用现有设计系统**：暗色主题、现有 token 和 `src/components/ui/` 组件，不另起一套。

## 4. 钱包与身份

### 4.1 连接后的检测顺序

1. **网络**：不在 BSC 时提示切换。
2. **钱包类型**：读取地址代码 `getCode(address)`：
   - 为空：普通钱包，正常；
   - 以 `0xef0100` 开头：EIP-7702 委托账户；
   - 其他非空代码：合约钱包（Safe 等）。

   后两种显示 `WalletTypeGuard` 警告："开盘前这个钱包无法参与首发、无法转币，也无法在买单市场交易。"
3. **Agent ID**：调用注册表 `handleOf(address)`：
   - 有名字：导航栏头像旁显示 `xxx.ai`；
   - 没有：显示"未持有 Agent ID"，并链接到 `/agent-id`。
4. **地区声明**：首次访问时展示一次，"本平台不向中国大陆、美国及受制裁地区的人士提供"，确认后写入 cookie。

### 4.2 用户资格状态（项目页使用）

| 状态 | 判断 | 展示 |
|---|---|---|
| 未连接 | — | "连接钱包查看你的参与资格" |
| 钱包不可用 | 合约钱包或 7702 | 红色警告，禁用买入 |
| 没有 Agent ID | `handleOf` 为空 | "首发需要 Binance Agent ID" + 领取指引；引导去买单市场 |
| 可参与 | 有 ID，剩余额度 > 0 | 显示 ID 名字、额度、已买、剩余 |
| 额度已用完 | 剩余额度 = 0 | "你的额度已用完"，引导去买单市场 |
| 已卖完 / 已截止 | — | "创世已结束"，引导去买单市场 |

### 4.3 Agent 模式（Agentic Wallet）

**背景**：Agent ID 绑定在 Binance Agentic Wallet 上，这个钱包主要通过 AI agent 或 `baw` 命令行操作，未必能在网页上直接连接（待实测，见 §19）。

**设计**：每个需要签名的操作按钮旁边，都提供"用 Agent 执行"入口，打开 `AgentModeSheet`：

```
┌ 用 Agent 执行 ───────────────────────────────┐
│ 操作：创世买入 0.5 BNB                         │
│ 预计得到：≈ 31,250 枚（滑点 1%）               │
│                                               │
│ ① 打开 Binance App → Agentic Wallet → 设置     │
│    → 开发者模式（已开启可跳过）                │
│ ② 把下面的指令发给你的 agent：                 │
│ ┌───────────────────────────────────────────┐ │
│ │ 请用 binance-agentic-wallet 执行合约调用：  │ │
│ │ 链：BSC                                     │ │
│ │ 合约：0xHook…                               │ │
│ │ 函数：buyGenesis(uint256,uint256)           │ │
│ │ 参数：500000000000000000, 30937…            │ │
│ │ value：0                                    │ │
│ │ （需要先授权 WBNB：approve(0xHook…, …)）   │ │
│ └───────────────────────────────────────────┘ │
│              [ 复制指令 ]  [ 复制 calldata ]   │
│ ③ 执行后回到这里，页面会自动识别你的交易       │
└───────────────────────────────────────────────┘
```

**要求**：

- 指令里的合约地址、函数、参数、`value` 必须由前端根据实时报价生成，不允许用户手填。
- 写明全部前置步骤（包装 WBNB、授权），按顺序编号。
- 监听用户地址的相关事件，交易上链后自动刷新，并显示成功状态。
- 后续可以发布一个 ToshX 专属的 Binance Skill，让 agent 直接说"在 ToshX 买入某项目 0.5 BNB"就能执行。不在 v1 范围内。

- **审核信息**：平台审核结论、风险标签、项目基金会地址及其修改记录、`projectAdmin` 地址。

## 7. 阶段一：预热

**主面板**

- 大倒计时："距离创世开始"。
- 参数卡：计价币、硬顶、单 ID 额度、创世时长、起始价 P、终点价 1.5P、开盘价 2P。

- 资格检查卡（§4.2）。持有 ID 时显示："你可以在开始后买入最多 X BNB。"
- 提醒：订阅项目的 Telegram 或 X 获取开始通知（外链）。
- 提示："越早越便宜，开始区块竞争激烈，建议提前准备好资金和授权。"

**提前准备**：开始前就允许用户完成包装 WBNB 和授权，开始时只需要一笔交易。

## 8. 阶段二：创世中

### 8.1 布局

```
┌ 创世买入 ──────────────────────────────────────────────┐
│ 当前价 0.00001786 BNB   已售 2,912,000 / 5,600,000      │
│ ████████████░░░░░░░░░░  52%    已募 46.7 / 100 BNB       │
│ 距离截止 05:12:44                                        │
│                                                         │
│ [ GenesisCurveChart：曲线 + 当前位置圆点 + 2P 虚线 ]     │
│                                                         │
│ 支付金额  [ 0.50 ] BNB    最大 0.50（你的剩余额度）     │
│ 预计得到  ≈ 27,640 枚                                   │
│ 平均成交价 0.00001809   成交后价格 0.00001832            │
│ 相对开盘价 2P：开盘时账面 ≈ 1.58 倍（不构成收益承诺）    │
│ 滑点 [1%]  最少得到 27,363 枚                            │
│                                                         │
│ [ 买入 ]            [ 用 Agent 执行 ]                    │
│ 买入即最终购买，没有退款。币立即到账，开盘前只能在普通钱包之间转账。 │
└─────────────────────────────────────────────────────────┘
```

### 8.2 交互规则

- **报价**：调用 `quoteGenesis(amount)`；输入停止 300 ms 后刷新，并在每个新区块刷新。
- **最大按钮**：取 min(余额, 剩余额度, 卖完所需金额)。
- **金额校验**：
  - 低于 `MIN_BUY`（0.01 BNB / 5 USDT）时禁用按钮。只有在补齐剩余额度时，才允许低于下限。
  - 超过剩余额度时自动截断，并提示"超出部分不会扣款"。
- **滑点**：默认 1%，可选 0.5% / 1% / 3% / 自定义；`minTokens` = 预计数量 × (1 − 滑点)。
- **首次买入**：弹出 `RiskConfirm`，必须勾选以下三项：
  1. 存款就是最终购买，没有退款；
  2. 开盘前只能在普通钱包之间转账，不能在任何 DEX 交易；
  3. 开盘后价格可能跌破成本。
- **成功弹窗**（改造 `DepositSuccessDialog`）：
  - 显示得到多少币、成交均价、交易哈希；
  - 按钮："把币添加到钱包""去买单市场看看"。

### 8.3 卖完时

- 进度条满格，显示"已卖完"。
- 主面板自动切换为"待开盘"，无需刷新页面。

### 9.1 主面板

```
┌ 等待开盘 ────────────────────────────────────────────┐
│ 创世已结束：卖出 5,600,000 枚，募集 100 BNB           │
│ 开盘价 2P = 0.00002857 BNB   池子：80 BNB + 2,800,000 枚 │
│                                                       │
│ 项目方专属开盘期剩余（共 48 小时）  31:21:10          │
│ 之后任何人都可以开盘（2026-10-28 18:00 起）           │
│                                                       │
│ [ 开盘 ]  ← 只对 projectAdmin 显示；专属期过后对所有人显示 │
│                                                       │
│ 在开盘前交易？→ [ 去买单市场 ]                        │
└───────────────────────────────────────────────────────┘
```

### 9.2 开盘按钮

- **何时可用**：专属期内只对 `projectAdmin` 地址可用；专属期结束后对所有已连接钱包可用。
- **确认弹窗**：说明本次开盘会做什么——以 2P 建池、LP 永久锁定、未卖出的币进黑洞、解除转账限制。
- **成功后**：整个页面切换为"交易中"。

### 9.3 开盘前转账

右栏"我的持仓"提供"转账"入口：

- 收款地址输入后先检查地址代码。对方是合约或 7702 账户时直接拦截，提示"开盘前不能转给合约地址"。
- 再读取代币的 `isReceiver(to)`。对方未登记时禁止发送，提示"对方需要先在 ToshX 登记收款地址"，并生成一条可以发给对方的登记链接 `/register?token=…`。参与过创世或挂过买单的钱包已经自动登记。
- 发送方是 Agentic Wallet 时，提示"收款地址需要先加入 Binance App 地址簿"，并提供 Agent 模式指令。

## 10. 阶段四：交易中

沿用并改造现有组件。

| 区块 | 组件 | 改动 |
|---|---|---|
| 池子交易 | `LiquidityPanel` / 交易面板 | 显示 1% 交易税（买入 0.7% 金库 + 0.3% 平台；卖出销毁） |
| 货架阶梯 | `BondingPanel`、`ShelfLadder` | 首档显示为 2P；展示当前天花板（1.05 × 参考价）以及当前能买到第几档；开盘头 30 分钟说明参考价使用 2P |
| 金库 | 金库卡片 | 储备余额、累计回购、累计销毁 |
| 买单市场 | 标签页 | 切换为"已开盘，只能撤单"，置顶显示"撤回我的买单" |

**货架面板必须显示**

- 当前档位、当前档价格、本档剩余数量；
- 天花板价格、参考价（现价 / TWAP 中较低者），以及"现在能买到第 N 档"；
- 同区块锁定提示："本区块池子已有交易，下个区块再买"；
- 平台刹车状态：暂停中时显示恢复时间。

**池子 vs 货架价格对比**：同时显示"从池子买"和"从货架买"的预估成本，帮用户选更便宜的一边。货架不收 1% 交易税，开盘初期通常更便宜。

### 11.2 订单簿规则

- 只显示买单，按价格从高到低排列，同价按挂单时间排列，每个价位汇总显示。
- 点击价位展开单张：单号、买家（缩略地址）、数量、挂单时间。
- **失效单单独折叠**，不计入最高买价、深度和托管总额统计。失效的情况有两种：
  - 价格 < 最新参与价 × 90%；
  - 买家地址现在带有代码。
- 深度和托管总额按**资金量**统计，不按数量，防止垃圾单把统计撑坏。
- 分页，每页 12 个价位。

### 11.3 快速卖出

- 输入数量后，前端从最高价往下选有效单，凑够数量为止，并显示用到了哪几张单。
- **创世仍在进行时**，优先选择价格比成交下限高至少 1% 的单；只比下限高一点点的单标为"临界"，默认不选。同时提示："创世仍在进行，价格下限会随买入上移，临界买单可能在成交时失效。"
- 显示成交均价、实收（扣除 1% 卖方手续费）、最低实收（默认滑点 1%，对应合约的 `minTotalOut`）。
- 选中的单在交易时被撤单或失效，会被合约跳过。实收低于最低值时整笔失败，用户不会多卖。
- **首次卖出弹出 `RiskConfirm`**："开盘价是 2P，开盘前卖出可能比开盘价便宜。"
- 步骤：授权代币给买单簿（开盘前只能授权给买单簿）→ 卖出。

### 11.4 挂买单

- 价格输入框的下限锁定为最新参与价，低于下限时禁止提交。
- 金额低于最低挂单额（0.01 BNB / 5 USDT）时禁止提交。
- 显示托管金额（含 1% 买方手续费预留），并说明"撤单时全额退回"。
- 提示："曲线价格上涨后，如果你的价格低于最新参与价的 90%，这张单会失效，只能撤单。"
- BNB 项目步骤：包装 WBNB → 授权买单簿 → 挂单。USDT 项目：授权 → 挂单。用 `TxStepper` 展示。
- 挂单钱包是合约或 7702 账户时禁止挂单（`WalletTypeGuard`）。

### 11.5 我的买单

- 列表字段：单号、价格、原始数量、剩余数量、托管余额、状态（有效 / 部分成交 / 已失效 / 已撤销 / 已成交）。
- 失效单置顶，标红并显示"撤单"按钮。
- 开盘后所有剩余的单都显示"撤单"，页面顶部显示汇总："你有 N 张买单可撤回，共 X BNB"。

### 11.6 成交记录

- 时间、价格、数量、买家、卖家、交易哈希。
- 最近成交价旁同时显示成交量，避免被单笔刷单误导。

## 13. 交易流程汇总

| 操作 | BNB 项目 | USDT 项目 | 合约调用 |
|---|---|---|---|
| 创世买入 | 走工厂原生入口（自动包装），一笔完成；或者包装 → 授权 → 买入 | 授权 → 买入 | `buyGenesis(maxPay, minTokens)` |
| 挂买单 | 包装 → 授权 → 挂单 | 授权 → 挂单 | `placeBid(hook, price, qty)` |
| 卖给买单 | 授权代币 → 卖出 | 同左 | `fill(bidIds, qtys, minTotalOut)` |
| 撤单 | 一笔 | 一笔 | `cancelBid(bidId)` |
| 开盘前转账 | 一笔（收款方须已登记） | 一笔（收款方须已登记） | `token.transfer(to, amount)` |
| 登记收款地址 | 一笔 | 一笔 | `token.registerReceiver()` |
| 开盘 | 一笔 | 一笔 | `factory.launch(hook)` 或 v2 对应入口 |
| 货架购买 | 授权 → 购买 | 同左 | `mintBondingCurve(amount, maxCost)` |
| 池子交易 | 沿用现有交易面板 | 同左 | 现有路由 |

**通用要求**

- 授权额度默认"本次所需金额"，可选"无限"。
- 已有足够授权时跳过授权步骤。
- 每一步都显示：等待签名 → 已提交（附哈希链接）→ 已确认 / 失败（显示合约报错的中文翻译）。
- 合约报错映射为中文提示，例如：`NoAgentId` →"你的钱包没有 Agent ID"；`CapExceeded` →"超过你的额度"；`TransferRestricted` →"开盘前不能转给合约地址"；`ReceiverNotRegistered` →"对方还没有登记收款地址"；`AgentRegistryUnavailable` →"Agent ID 服务暂时不可用，请稍后再试"。

### 14.1 链上直读（wagmi / viem）

| 数据 | 来源 |
|---|---|
| 阶段、开盘状态、价格、已售、已募 | Hook：`launched`、`sold`、`raised`、`currentGenesisPrice()`、`soldOutAt`、`genesisDeadline`、`basePrice` |

**刷新节奏**

- 创世中、待开盘：每个新区块刷新（约 3 秒）。
- 其他阶段：每 15 秒刷新。
- 用户自己的交易确认后立即刷新。

### 14.2 事件索引（新增）

现在前端没有索引服务。订单簿汇总、成交历史、个人记录都需要索引。

- **实现**：定时任务（Vercel cron 或 GitHub Actions，沿用现有 `watch-ping` 机制）拉取事件，写入 Supabase。
- **新表**：
  - `genesis_buys`：项目、买家、Agent ID、金额、数量、价格、区块、哈希；
  - `bids`：单号、项目、买家、价格、原始数量、剩余数量、托管、状态；
  - `bid_fills`：单号、卖家、数量、价格、区块、哈希；
  - `project_events`：`Launched`、`ProjectFundChanged`、`FundWithdrawn`。
- **新 API**：
  - `GET /api/projects/[address]/orderbook`：按价位汇总的有效单和失效单；
  - `GET /api/projects/[address]/trades`：成交记录；
  - `GET /api/portfolio/[wallet]`：个人汇总；
  - `GET /api/bids?owner=`：我的买单。
- **一致性**：用户下单前，前端用链上直读复核买单的剩余数量和失效状态；索引只用来展示，不作为成交依据。
- **延迟**：索引延迟目标 ≤ 15 秒；页面显示"数据更新于 xx 秒前"。

## 18. 验收标准

1. **资格**：以下五种钱包在项目页的显示都与 §4.2 一致：未持有 ID、持有 ID、额度用完、合约钱包、7702 账户。
2. **创世买入**：
   - 报价与链上成交数量的差异在滑点范围内；
   - 额度截断、`MIN_BUY`、卖完切换阶段都按规则执行。
3. **Agent 模式**：生成的指令交给 agent 执行后，交易参数和网页直连完全一致，页面能自动识别交易已上链。
4. **待开盘**：
   - 专属期内只有 `projectAdmin` 能看到可用的开盘按钮，专属期过后所有人都能看到；
   - 开盘后页面无需刷新即切换到交易中。
5. **买单市场**：
   - 失效单不计入最高买价和深度；
   - 快速卖出的选单和实收计算与合约一致；
   - 挂单价格下限与链上一致；
   - 开盘后只能撤单。
6. **转账**：开盘前转给合约地址或未登记地址，在前端就被拦截；登记页一笔交易完成登记。
7. **风险确认**：每个项目首次执行创世买入、卖出前，都必须完成勾选确认。
8. **数据**：索引延迟不超过 15 秒；成交前用链上数据复核，复核结果与索引不一致时以链上为准。
9. **多语言**：中文、英文完整，无漏译。
10. **移动端**：创世买入、卖出、挂单、撤单四个核心操作在 375 px 宽的屏幕上都能完成。

与本文不同或尚未实现之处：

1. **索引**：由 `/api/v2/index` 推进（需 `CRON_SECRET`），读接口在索引超过 10 分钟未更新时返回 503，前端自动改为直接扫链上日志。本文要求的「延迟不超过 15 秒」需要外部定时器每 1–2 分钟调用一次；`vercel.json` 只放了每日一次的兜底。
2. **快速卖出**：只路由到高于成交下限 1% 以上的买单（§11.3 的建议），滑点保护 1%。
3. **风险确认**：每个项目在本浏览器勾选一次（存在 localStorage），创世买入和卖出都要求勾选；挂买单不要求。
4. **Agent 模式（§4.3）**：`components/v2/AgentModeSheet.tsx`。以下操作都有「用 Agent 执行」入口：创世买入、挂单、卖出、撤单、登记、转账、开盘、提取项目资金、货架买入。
   - 指令和 calldata 由前端按实时报价生成，包装 WBNB、授权等前置步骤按顺序编号；
   - 弹窗做成按钮下方的展开面板（组件库没有弹窗）；
   - 用户填上 Agent 钱包地址后，页面每 5 秒查一次这个地址的 nonce，发现新交易就刷新；这个地址也用于未连接钱包时显示「我的挂单」「持仓」和登记状态；
   - 合约要求签名方是没有代码的普通钱包（`tx.origin` 且无代码）。如果 Agentic Wallet 是合约钱包或 7702 账户，这些指令会被合约拒绝，见 §19 实测。
5. **开盘前转账（§9.3）**：项目页右栏「我的持仓」，`components/v2/TransferPanel.tsx`。先查收款地址是否有代码、是否已登记；未登记时生成 `/register?token=…` 链接供复制。也提供 Agent 指令，并提示「收款地址需要先加入 Binance App 地址簿」。
6. **成交记录**：只在市场页显示最近 50 笔（来自索引）；索引不可用时整块隐藏，不影响下单。
