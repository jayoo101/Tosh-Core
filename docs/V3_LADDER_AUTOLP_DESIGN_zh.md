## 3. 货架收入：二级买币配池

### 资金流

```
用户买 x 个币，付款 c（逐档求和，与 v2 相同）
  1%  → 阶梯金库（平台回购池）
  19% → projectAdmin（Circuit 收入金库）
  80% → hook：一部分在官方池买入 TOSH，再和剩余报价币一起加进 hook 的全区间仓位
用户收到 x 个新铸 TOSH
```

配池不再新铸配对代币，阶梯之外没有额外增发。hook 买到的币锁进 LP，相当于从流通中移除。

### `mintBondingCurve` 新流程

1. v2 的检查全部保留：平台暂停、同区块锁定、`min(现价, TWAP)` 平价天花板、`maxCost`。
2. 逐档循环算出 `cost`，更新阶梯状态（与 v2 相同）。
3. 从买家拉款：1% 给阶梯金库，19% 给 `projectAdmin`，80% 给 `ToshAutoLp`。
4. 给买家铸 `x`。
5. 最后调用 `ToshAutoLp.deposit(80%)`。它把钱记入该项目的挂起额，尝试加池；条件不满足就留在挂起里，**不会让这笔货架交易失败**。

天花板在循环开始前算一次，循环中没有 swap，所以 v2“天花板只算一次”的前提仍然成立；配池的 swap 发生在循环之后。

### 为什么是独立合约 `ToshAutoLp`

hook 已贴近 EIP-170 上限（v3 现为 24,527 字节，余 49 字节），装不下买币加池的逻辑。所以 hook 只转账并调用 `deposit`，其余都在 `ToshAutoLp`（每个市场一个，`setFactory` 一次性绑定，且要求该 factory 的 hook 实现指向自己）。它按 hook 分账：`pendingQuote[hook]`、`pendingToken[hook]` 是该项目池子还欠着的钱和币，`totalQuoteAdded` / `totalTokenAdded` 是累计加进去的量。LP 仓位归 `ToshAutoLp` 所有，合约没有移除流动性的函数，所以永久锁定。

### 加池条件与执行

满足以下全部条件才执行，否则发出 `Deferred(reason)` 并保留挂起：

- 挂起额大于零；
- hook 的 TWAP 已成熟（`twapSqrtPriceX96() != 0`）；
- 现价的 sqrt 不低于 TWAP 的 sqrt × (1 − 0.99%)，即代币现价不高于 TWAP 约 2%；
- 池子有流动性。

`deposit` 来自 `mintBondingCurve` 内部，而后者已经拒绝了本区块价格被推动超过 10 tick 的情况，所以不再重复检查同区块。

执行时：

1. 取 `q = min(挂起额, 池中报价币虚拟储备 × 2%)`，大约一半用于买币，所以单次买入约为池子的 1%。
2. 用常数乘积的 zap 公式算出买入量 `s`，扣除 1% 交易税和池子手续费（读取池子实际费率，v3 为 0.2%），使剩余报价币和买到的币符合买入后的价格比例。swap 另设 sqrt 价格不超过 2% 的硬性限价作为兜底。
3. 在 `vault.lock` 里依次做 exact-input swap 和 `modifyLiquidity`（全区间），按净额与 Vault 结算。
4. 凑不齐比例的零头留在挂起里，下次一起加。已有仓位累积的手续费会在同一次结算中计入挂起，自动复投。

### `flush(hook)`

任何人都可以调用，条件同上，另外要求本区块该池还没有 swap（`lastSwapBlock < block.number`），否则 revert `PriceMovedThisBlock`。什么都没加进去时 revert `NothingAdded(reason)`。

### hook 自己的买单

Infinity 的 `CLHooks` 不会跳过 hook 自己发起的 swap，`beforeSwap` / `afterSwap` 照常回调。因此：

- **照常收交易税**：不需要豁免分支。满募时成本约为货架收入的 0.4%，按买入税规则分：60% 给项目方，40% 进阶梯金库。
- **计入同区块锁定和 TWAP 观测**：`afterSwap` 的区块戳和 `_writeObservation()` 放在任何豁免之前（v2 已经如此）。hook 买入把价格推动超过 10 tick 后，本区块后续的货架铸造会 revert，相当于每个区块只成交一笔较大的货架单。
- **跳过顺带回购**：`afterSwap` 里 `sender == autoLp` 时不调用阶梯金库的 piggyback poke。原因是货架买家的 gas 需要可预测，回购也不应嵌套在 `ToshAutoLp` 已打开的 Vault 会话里。回购仍由普通交易或 `pokeBuyback()` 触发。

### 为什么保留 TWAP

1. **天花板**：项目方自己买货架能拿回 19%，相当于有 19% 折扣。如果只看现价，他可以短时拉盘、解锁一大段货架、再砸盘。取 `min(现价, TWAP)` 后，他必须把高价撑住 30 分钟，这期间套利者会一直卖给他。
2. **配池偏离保护**：防止跨区块拉盘后让 hook 在高位买币。同区块的夹单由同区块锁定挡住，单笔 1% 上限让夹单利润盖不住来回约 2% 的税费。

## 4. 创世与开池

逻辑与 v2 相同，只换常量：

- `GenesisCurve.SALE_SUPPLY`、`N = 1.25 × SALE_SUPPLY`；
- `GENESIS_SUPPLY = 1.5 × SALE_SUPPLY`；
- `launch()` 中 `lpTokens = lpReserve × N / (2H)`，满募时等于卖出量的一半，开盘价仍为 2P；
- 未卖完的部分照旧铸给 `0xdead`，`sold + lpTokens + burned = GENESIS_SUPPLY`；
- `tierSize = TIER_SIZE × raised / hardCap`，部分募集时阶梯等比缩小（与 v2 相同）。

## 7. 测试清单

- **不变量**：总供应 ≤ 2.1B；阶梯卖出 ≤ `TIER_COUNT × tierSize`；LP 无法移除；`ToshAutoLp` 持有的报价币和代币等于各项目挂起额。
- **不变量**：货架铸造的逐档循环不改变现价；配池只在循环之后改变现价。
- **单测**：三方分账；`ToshAutoLp` 的每个推迟原因；单次上限和挂起累积；`flush` 在同区块 swap 之后和无挂起时被拒；`autoLp` 的买单照常收税且不触发 piggyback；配池买入后本区块后续铸造 revert；挂起额始终等于合约实际持有量。
- **创世**：新常量下开盘价仍为 2P；部分募集的燃烧量和 `tierSize` 缩放。
- **`TIER_STEP_E18`**：`_powE18(STEP, 9999) ≤ 1e33` 且 `_powE18(STEP + 1, 9999) > 1e33`。
- **v2 回归**：v2 测试套件不受影响。

## 8. 二级交易税与池子手续费（已定）

| 项目 | v2 | v3 |
| --- | --- | --- |
| 买入税（收报价币） | 1%：0.7% 回购池，0.3% 平台 | 1%：0.6% 项目方（`projectAdmin`），0.4% 回购池 |
| 卖出税（收代币） | 1% 销毁 | 不变 |
| 池子兑换手续费 | 0.3% | 0.2% |
| 创世 LP 手续费 | 报价币给项目方，代币销毁 | 报价币给平台（`platformFeeRecipient`），代币销毁 |

- 用户每笔交易的总成本从 1.3% 降到 1.2%。

- 阶梯金库自己的回购交易照旧免税，避免回购嵌套和资金回流。
- 已知代价：项目方自买时交 1% 拿回 0.6%，刷买单的净成本约 0.4%。
- 合约：`PROJECT_SWAP_TAX_BPS = 60`（替换 `PLATFORM_SWAP_FEE_BPS`），`POOL_FEE = 2000`，事件 `ProjectSwapTaxPaid`。hook 24,551 字节，余 25 字节。

## 9. 货架阶梯的 Agent ID 门槛（已实现）

- 货架铸造需要 Agent ID；创世阶段的额度不沿用，进入货架阶段后每个 ID 重新计算。
- 额度按项目分开：同一个 ID 在每个项目的货架上各有一份，整个货架阶段累计计算，不按天重置。
- 初始额度：USDT 市场 500 USDT，BNB 市场 0.7 BNB。数额写在各自的 factory 上（`shelfCapPerAgent`），由 Safe 通过 `setShelfCapPerAgent` 调整，不接喂价；调整后对所有项目立即生效，调低到已用额度以下的 ID 就不能再铸。
- 记账在 factory：hook 的 `mintBondingCurve` 算出 cost 后调用 `factory.bookShelfMint(buyer, cost)`。factory 依次检查：货架是否暂停（`LadderHalted`）、买家有没有 ID（`NoAgentId`）、加上这笔是否超额（`ShelfCapExceeded`），通过后记账。超额整笔回退，不做部分成交。
- 已用额度取“这个 ID 已用”和“这个钱包已用”中较大的一个，两边同时记账：换新 ID 或把 ID 转给别的钱包，都不会多出一份额度。
- 查询：`shelfRemaining(hook, account)` 返回还能花多少，没有 ID 返回 0；`shelfSpentByAgent`、`shelfSpentByWallet` 可查已用。
- **市场价上限保留**。上限挡的是高于市价的铸造，只有拿返还的一方（项目方，v3 下 19%）会这样做：去掉上限后，货架价不超过市价约 22% 时铸了就砸就有利可图，而项目方可以自备多个 ID，限额挡不住。Agent ID 和限额解决的是巨鲸囤货架和套利集中，两者互补。
- 额度记账放在 hook 之外（factory），hook 现在 24,562 字节，离上限还有 14 字节。
