## 1. 一页摘要

### 1.1 一句话

持有 Binance Agent ID 的用户在创世期按"越早越便宜"的价格买币，买完立即到账。开盘前只能在普通钱包之间转账，或在官方只显示买单的市场里卖出。开盘时以第一个参与价的 2 倍建池，之后由货架阶梯按真实需求逐档增发。

### 1.2 时间线

```
创建项目
  │  项目方设定：计价币（BNB/USDT）、硬顶、单 ID 额度、创世时长、基金会地址
  ▼
创世发售 ── 持 Agent ID 的 EOA 按曲线买入（P → 1.5P），买完即到账
  │         每笔 20% 记入项目基金会（随时可提），80% 留作建池资金
  │  同时开放：普通钱包之间转账 ＋ 买单簿（只有买单）
  ▼
卖完 / 到截止时间
  │  48 小时内由项目方开盘；超过 48 小时任何人都能开盘，没有过期
  ▼
开盘 ── 80% 资金 + L 枚币按 2P 建池，LP 永久锁定；未卖出的币进黑洞；解除转账限制
  ▼
开盘后 ── 池子自由交易（1% 税）＋ 货架从 2P 起逐档解锁 ＋ 金库回购销毁；买单簿只能撤单
```

### 1.3 v1 与 v2 对比

| 模块 | v1（现状） | v2（本设计） |
|---|---|---|
| 防女巫 | PoG：链下扫描 gas 历史，pogSigner 签名额度 | Binance Agent ID：合约直接读链上注册表，一个 ID 一份额度 |
| 创世定价 | 存款后按比例分配 4.62M | 按卖出量线性涨价，P → 1.5P，**买完立即到账** |
| 开盘前代币 | 不存在 | 在用户手里，只能在普通钱包之间转账 |
| 开盘前交易 | 无 | 官方买单簿，只显示买单，买卖各收 1% 归平台 |
| 募集资金 | 90% 建池，10% 推荐佣金 | 20% 项目基金会，80% 建池；不设推荐佣金 |
| 退款 | 有 | **取消** |
| 最低募集额 | 由阶梯可行性决定 | **取消**（只设单笔最低参与额） |
| 开盘 | 多签触发，窗口过期则退款 | 项目方 48 小时内触发，之后任何人可触发 |
| 开盘前收款 | — | 只能转给已登记的普通钱包（参与创世、挂买单时自动登记） |
| 开盘价 | 0.9 × 募集 ÷ 3.78M | **2P** |
| 货架首档 | 开盘价 × 1.05 | **2P** |
| 货架其他规则 / 池子税 / 金库 | — | 全部沿用 v1 |

## 2. 设计目标与边界

**目标**

1. 用 Binance Agent ID 替换 PoG，去掉链下扫描服务和 pogSigner 私钥这一单点。
2. 参与即拿币。开盘前可以自由转账，但链上不能形成任何 AMM 价格。
3. 越早参与价格越低，首尾价差 1.5 倍，开盘价对所有创世参与者都高于成本。
4. 开盘前提供唯一的官方二级市场：只有买单的订单簿。
5. 货架阶梯、永久锁定 LP、金库单向回购这些核心机制不变。

**必须始终成立的三条不变量**

1. **资金永远有出口**：没有退款，所以开盘一定能完成，任何人、任何外部合约都不能卡住它。
2. **代币没有管理员**：代币不设 owner，转账限制只能由 Hook 解除一次，之后不能恢复。
3. **托管资金只有两个出口**：买单簿的托管资金只能通过买家撤单或成交离开。

**不做的事**

- 不升级、不迁移已上线项目。
- 不承诺挡住链下 OTC，只挡链上价格发现。

## 4. Binance Agent ID 接入

### 4.1 已核实的事实

| 项目 | 内容 |
|---|---|
| 形态 | ERC-721 `.ai` 名字，soulbound（不可转让），永久有效 |
| 读取接口 | `handleOf(address) → string`（空字符串表示没有）；`ownerOfHandle(string) → address` |
| 获取条件 | Binance 账户 + MPC 钱包 + Agentic Wallet |
| 数量限制 | **一个 Binance KYC 账户最多 1 个 Agent ID**（已确认） |
| 钱包类型 | 普通 EOA：抽查 4 个持有地址（`baguz11`、`emzy001`、`yourfather`、`xiao00`），代码长度都为 0，也没有 7702 委托 |
| 合约交互 | 支持 `contract-call`，需要在 Binance App 打开"开发者模式"；转出只能发往地址簿中的地址 |
| 注册表管理员 | owner `0x457C1fd14750c6c30886A2f2B57F1eF44B095882`，可以通过 `AdminRegistered` 直接发 ID |

### 4.2 校验方式：链上直读，不用签名

创世买入时，Hook 依次执行：

1. `handle = handleOf(msg.sender)`，结果为空则拒绝。
2. 一致性校验：`ownerOfHandle(handle) == msg.sender`。
3. `agentKey = keccak256(bytes(handle))`，与注册表的 tokenId 一致。
4. **额度按 `agentKey` 记账，不按地址记账**。同一个名字即使以后换绑地址，也不能再领一次。

注册表地址写成常量，平台不运行任何签名服务。

**调用保护**：两次注册表读取都用限定 gas 的 `staticcall`（上限 100,000 gas），并用 `try/catch` 包住。调用失败、超出 gas 或返回数据格式不对时，统一报错 `AgentRegistryUnavailable()`。注册表出问题只会让创世买入暂时失败，不影响开盘、转账和买单簿。

### 4.3 额度

- 按计价币金额（BNB 或 USDT）计算，记为 `perAgentCap`。
- 项目方在创建时于平台上下限内自选，创建后不可修改。
- 一个 ID 可以分多次买，累计不超过额度。

### 4.4 信任假设（写入披露）

- 一个 KYC 账户只能开 1 个 ID，所以一份额度基本对应一个 KYC 身份。但 KYC 账户本身可能被买卖，**不能宣传为"一人一份"**。
- 注册表管理员（SPACE ID / Binance）可以直接发 ID。
- 没有 Binance 账户、或身处 Binance 不服务地区的用户不能参与首发，但可以在买单簿买入。

## 5. 创世发售：按卖出量线性涨价

### 5.1 常量与参数

| 名称 | 数值 | 说明 |
|---|---|---|
| `GENESIS_SUPPLY` | 8,400,000 | 创世总量 |
| `SALE_SUPPLY`（C） | 5,600,000 | 可卖给参与者的上限 |
| `LP_SUPPLY_MAX` | 2,800,000 | 卖完时进池数量 |
| `hardCap`（H） | 项目方填写 | 卖完时的募集总额 |
| `P` | `H ÷ 7,000,000` | 合约推导出的第一枚价格 |
| 终点价 | `1.5P` | 最后一枚价格 |

推导：卖完时平均价为 1.25P，所以 H = 5.6M × 1.25P = 7M × P。

### 5.2 价格曲线

已卖出 s 枚时，下一枚的价格：

```
price(s) = P × (1 + 0.5 × s / C)
```

从 s 买到 s + x 的总价：

```
cost(s, x) = P × [ x + 0.25 × ((s + x)² − s²) / C ]
```

已知支付金额 a，反解 x 就是解下面这个二次方程：

```
(0.25P / C) · x² + P · (1 + 0.5s / C) · x − a = 0
```

实现要求：

- 一律用 OpenZeppelin `Math.mulDiv`（512 位中间值）和 `Math.sqrt`，不直接计算 `b² − 4ac`。
- 舍入始终对协议有利：x 向下取整，再用 x 正向重算 `cost`（向上取整），以重算结果作为实际扣款。

### 5.3 买入流程 `buyGenesis(maxPay, minTokens)`

1. **检查**
   - 处于创世期，未卖完，未开盘；
   - 调用者是 EOA：`msg.sender == tx.origin`，且代码长度为 0；
   - 调用者持有 Agent ID（§4.2），额度未用完；
   - `maxPay ≥ MIN_BUY`。最后一个人补齐剩余额度时可以低于这个值。
2. **截断**：实际成交金额 = min(maxPay, 个人剩余额度, 卖完所需金额)。
3. **计算**：按曲线算出 x，检查 `x ≥ minTokens`（滑点保护）。
4. **卖完尾差**：如果成交后剩余量低于 `DUST`，把剩余量一起给这位买家，按曲线补收差价，直接视为卖完。
5. **扣款**：`SafeERC20.safeTransferFrom` 只拉取正向重算出的 `cost`，不多拉，所以不存在找零。
6. **记账**：`fundAccrued += 20% × cost`；`lpReserve += cost − 20% × cost`。
7. **铸币并登记**：直接 `mint(x)` 给用户；如果用户还没登记为收款地址，调用 `token.registerFor(buyer)`（§7.1.1）。
8. **更新状态**：`sold`、`raised`、`agentSpent[agentKey]`；卖完时记录 `soldOutAt`。
9. **事件**：`GenesisBuy(buyer, agentKey, paid, tokens, priceAfter)`。

整个函数遵循 CEI（先检查、再改状态、最后外部调用），并加 `nonReentrant`。

**计价币**：统一按 ERC-20 结算。BNB 项目内部用 WBNB；用户发送原生 BNB 时，由工厂的原生入口先包装成 WBNB（沿用 v1 做法）。USDT 项目使用 BSC USDT。

### 5.4 示例（hardCap = 100 BNB）

| 项目 | 数值 |
|---|---|
| P | ≈ 0.00001429 BNB |
| 最后一枚（1.5P） | ≈ 0.00002143 BNB |
| 开盘价（2P） | ≈ 0.00002857 BNB |
| 开盘时池子 | 80 BNB + 2.8M 枚 |
| 项目基金会累计 | 20 BNB |
| 开盘 FDV（21M × 2P） | ≈ 600 BNB |
| 单 ID 额度 0.5 BNB 时 | 至少需要 200 个 ID 才能卖完 |

### 5.5 开盘时各参与者的账面情况

| 参与者 | 成本 | 开盘时 |
|---|---|---|
| 第一个 | P | 2.0 倍 |
| 平均 | 1.25P | 1.6 倍 |
| 最后一个（卖完时） | 1.5P | 1.33 倍 |

## 6. 开盘（launch）

### 6.1 触发条件

- **前提**：`raised > 0`，并且已卖完或已到创世截止时间。
- **起算点**：`launchStart` = 卖完时间（如果卖完了），否则为创世截止时间。
- **`launchStart` 起 48 小时内**（`ADMIN_LAUNCH_WINDOW = 48 hours`）：只有 `projectAdmin` 可以触发。
- **48 小时之后**：任何人都可以触发，没有过期时间。
- 缩短的原因：如果项目方私钥丢失、签名人联系不上或者故意拖延，用户手里的币最多被限制 48 小时，而不是 7 天。

### 6.2 可达性约束（不变量 1）

- 不受工厂暂停、黑名单、货架刹车影响。
- 不调用 `projectFund`，也不调用 Agent ID 注册表。
- `MIN_BUY` 保证只要 `raised > 0`，`lpReserve` 就足以产生非零流动性。

### 6.3 内部步骤

整个函数加 `nonReentrant`，所有状态在外部调用之前写完。

1. `launched = true`，调用代币的 `openTrading()`。这一步必须在任何代币进入 Vault 之前。
2. `p0 = 2P`；`shelfP0 = p0`（`SHELF_PREMIUM_BPS = 10000`）。
3. 进池数量：`L = lpReserve ÷ 2P`。卖完时 `lpReserve = 0.8H`，L 正好是 2.8M。
4. `mint(hook, L)`，然后**只用 `lpReserve`** 和 L 枚币，按 p0 初始化官方池并加流动性。LP 永久锁定，沿用 v1 路径。
5. 外部误转入 Hook 的计价币（余额 − `lpReserve` − `fundAccrued`）转给平台。开盘价因此不会被外部转账推离 2P。
6. **黑洞**：`mint(DEAD, 8.4M − sold − L)`。卖完时这部分为 0。
7. 初始化 TWAP 观测点。保留同区块锁定，开盘区块内不能买货架。
8. 事件：`Launched(raised, lpReserve, L, burned, p0)`。

数量校验：没卖完时 sold + L ≈ 1.4 × sold < 8.4M；卖完时 sold + L = 8.4M。总供应量上限 21M 不变。

## 7. 开盘前的转账规则

### 7.1 规则（写在代币 `_update` 里，只在 `tradingOpen == false` 时生效）

| 情况 | 结果 |
|---|---|
| `from == 0`：Hook 铸币，包括给用户、给 Hook、给黑洞 | 允许 |
| 直接 `transfer`：`_msgSender() == from == tx.origin`；from 和 to 的代码长度都为 0；**并且 `to` 已登记为收款地址** | 允许 |
| 买单簿发起的 `transferFrom`：`_msgSender() == BID_BOOK`；from 和 to 的代码长度都为 0；**并且 `to`（买家）已登记**（买单簿自身要求调用者 `msg.sender == tx.origin`） | 允许 |
| 其他所有情况：合约收发、第三方 `transferFrom`、7702 账户、构造函数里发起的转账、转给未登记的地址 | 拒绝 |

- `approve`：开盘前只允许授权给 `BID_BOOK`。
- 开盘后恢复为普通 ERC-20，不再做任何检查，登记表也不再使用。

**为什么要加 `tx.origin`**：合约在构造函数执行期间代码长度为 0，只看代码长度会被绕过。要求 `from == tx.origin` 后，只有发起这笔交易的 EOA 本人才能转出。这里的 `tx.origin` 只用来判断"是不是 EOA 本人直接操作"，不用于权限认证，而且开盘后不再检查。

### 7.1.1 收款地址登记

**要堵的漏洞**：CREATE2 可以事先算出一个还没部署的合约地址，这个地址此时代码长度为 0，单看代码会被当成普通钱包。有人可以：

1. 先把币转到这个地址；
2. 再把合约部署上去；
3. 合约虽然转不出币，但可以在内部记账，开盘前就卖"提币权"收 BNB，开盘后再把币分给买家。

这样一来，开盘前就有了一个链上影子交易池。

**规则**：开盘前，收款方必须是已登记的地址。代币里维护 `isReceiver[address]`，有三种登记方式：

| 方式 | 谁来登记 | 条件 |
|---|---|---|
| 自己登记 | 用户调用 `token.registerReceiver()` | `msg.sender == tx.origin` 且代码长度为 0 |
| 创世买入时自动登记 | Hook 在 `buyGenesis` 里调用 `token.registerFor(buyer)` | 只有 `HOOK` 能调；Hook 已校验 buyer 是 `tx.origin` |
| 挂买单时自动登记 | 买单簿在 `placeBid` 里调用 `token.registerFor(bidder)` | 只有 `BID_BOOK` 能调；买单簿已校验 bidder 是 `tx.origin` |

**为什么能堵住**：登记要求登记人就是发起交易的 EOA 本人（`tx.origin`）。没部署的合约地址没有私钥，永远发不出交易，所以永远登记不了，也就永远收不到币。

**补充说明**

- 登记只增不减，没有任何人能删除或代替别人登记；平台和项目方都没有管理权限。
- 登记过的钱包如果之后做了 7702 委托，代码长度就不再为 0，仍然会被拒绝。
- 收款方未登记时报错 `ReceiverNotRegistered(to)`，前端提示对方先登记（一笔交易，几乎没有成本）。
- 黑洞地址和 Hook 收币都走 `from == 0`（铸币）路径，不需要登记。
- 开盘后登记表不再使用，不影响任何正常交易。

### 7.2 开关

- `openTrading()` 只能由 Hook 调用一次，单向不可逆，代币没有 owner。
- `HOOK` 和 `BID_BOOK` 地址在代币初始化时写入，之后不可修改。`HOOK` 就是持有 `MINTER_ROLE` 的同一个地址。
- 开盘后每次转账只多读一个布尔值，gas 影响可以忽略。

### 7.3 能挡住的

- 往 PancakeSwap Infinity Vault、V2/V3 pair 或任何自建池注入代币。
- 先打到空地址再部署合约：未部署的地址无法登记，一开始就收不到币（§7.1.1）。即使是已登记的地址，部署合约后发送方有代码，也转不出去。
- 基于 CREATE2 延迟部署的托管合约、影子交易池（§7.1.1）。
- 在构造函数里转账（`tx.origin` 校验）。
- 第三方托管撮合合约（不能使用 `transferFrom`）。
- **官方池不能被抢先初始化**：Hook 的 `beforeInitialize` 要求 `sender == address(this)`，否则报错 `UnauthorizedInitialization`（v1 现有代码，v2 沿用）。PoolKey 里包含 Hook 地址，所以别人用其他 Hook 或不用 Hook 初始化的池，是另一个 PoolId，不会和官方池冲突，也就不会让 `launch()` 因为"池子已初始化"而失败。
- 第三方空池（其他 Hook 或无 Hook）可以初始化，但开盘前没有代币可以注入，形不成价格。

### 7.4 挡不住的（写入披露）

- 链下 OTC。
- 开盘后第三方另建无 Hook 的池子（与 v1 相同）。

### 7.5 对用户的影响

- **收款方需要先登记**：参与过创世或挂过买单的钱包已经自动登记。其他钱包要先调用一次 `registerReceiver()`，才能在开盘前收币。
- **Agent ID 钱包（Agentic Wallet）开盘前可以正常转账**，它在链上是 EOA。限制来自 Binance App 本身：
  - 转出只能发往地址簿中的地址；
  - 自带的"发送"可能识别不了新币，这时要用开发者模式直接调用代币的 `transfer`；
  - 在买单簿卖币，要先用开发者模式 `approve` 买单簿，再调用 `fill`。
- **EIP-7702**：BSC 已在 2025 年 Pascal 硬分叉中启用。
  - 用户如果在 MetaMask 等钱包里升级成"智能账户"（带委托），开盘前不能参与首发，也不能转币。
  - 如果 Binance 以后把 Agentic Wallet 升级成 7702 账户，也会受影响，届时只能提示用户撤销委托。
  - 不放行 7702 账户的原因：委托代码可以执行任意逻辑，可能被做成 AMM。
- **合约钱包**（Safe 等）开盘前不能参与首发，也不能转币。

## 8. 买单簿 `ToshBidBook`

参考 [Ptah 市场页](https://ptah.trade/market)：买家锁定资金挂买单，持币人只能卖给买单，页面上没有卖单。

### 8.1 定位

- 全链部署一个，服务所有 v2 项目。
- 不可升级，没有管理员。
- 开盘前是官方唯一的交易场所；开盘后停止新挂单、停止成交，只能撤单。

### 8.2 参数

| 项目 | 规则 |
|---|---|
| 计价币 | 与项目一致（WBNB 或 USDT），**只收发 ERC-20**，前端负责包装原生 BNB |
| 价格单位 | 每 1e18 枚代币对应多少计价币 |
| 挂单资格 | 任何 EOA，不要求 Agent ID |
| 最低挂单金额 | 0.01 BNB / 5 USDT |
| 最小成交量 | 1 枚（`MIN_FILL_QTY`） |
| 买方手续费 | 1%，只在成交时收 |
| 卖方手续费 | 1%，只在成交时收 |
| 手续费去向 | 平台多签（部署时写死），先记账、再提取 |
| 挂单价下限 | 不低于挂单当时的最新参与价 |
| 成交价下限 | 不低于成交当时最新参与价的 90%（`FILL_FLOOR_BPS = 9000`） |
| 过期 | 无，挂到撤单为止 |

**最新参与价** `currentGenesisPrice()`：还没有人参与时为 P；卖出过程中是曲线上下一枚的价格；卖完后冻结在 1.5P。

### 8.3 函数

**`placeBid(hook, price, qty)`**

- 前提：
  - 项目已在工厂登记、尚未开盘；
  - 挂单人是 EOA（`msg.sender == tx.origin`，代码长度为 0）。
- `price ≥ currentGenesisPrice()`，金额不低于最低挂单额。
- 托管金额 `escrow = G + ceil(G × 1%)`，其中 `G = ceil(price × qty ÷ 1e18)` 是整单货款，后一项是买方手续费预留。
- 如果挂单人还没登记为收款地址，调用该项目代币的 `registerFor(bidder)`，保证成交时代币能转进来（§7.1.1）。
- 事件：`BidPlaced(bidId, hook, bidder, price, qty)`。

**`cancelBid(bidId)`**

- 只有挂单人能调用，任何时候都可以，开盘后也可以。
- 退还剩余托管资金，包括没用到的手续费预留。
- 事件：`BidCancelled(bidId, refund)`。

**`fill(bidIds[], qtys[], minTotalOut)`**

- 前提：项目尚未开盘；卖家是 EOA（`msg.sender == tx.origin`）。
- **以下两类单直接跳过、不成交**，交易继续处理下一张，不整笔回滚：
  1. 价格低于 `currentGenesisPrice() × 90%` 的单；
  2. 买家地址现在带有代码的单（例如挂单后做了 7702 委托）。
- 对每张有效的单，用**累计差额法**记账。每次都从"累计已成交数量"重新计算累计金额，再减去上一次的累计值，避免多次部分成交时取整误差越积越多：
  1. 新累计成交量 `F' = F + q`；
  2. 累计货款 `Gc(F) = ceil(price × F ÷ 1e18)`，本次货款 `gross = Gc(F') − Gc(F)`；
  3. 累计买方费 `Bc(F) = ceil(Gc(F) × 1%)`，本次买方费 `buyerFee = Bc(F') − Bc(F)`；
  4. 本次卖方费 `sellerFee = floor(gross × 1%)`；
  5. `token.transferFrom(seller, bidder, q)`，代币直接从卖家到买家，合约不经手；
  6. 托管扣除 `gross + buyerFee`；卖家实收 `gross − sellerFee`；`buyerFee + sellerFee` 记入 `feesAccrued`。
- **为什么不会下溢**：`Gc` 和 `Bc` 都随 F 单调不减，并且 F = qty 时正好等于挂单时的 G 和 `ceil(G × 1%)`。所以全部成交时扣除的总额恰好等于 `escrow`，任何时刻剩余托管都不会小于 0。单张单成交完时，剩余托管必然为 0。
- **撤单**：直接退还该单当前的全部剩余托管，不再重新计算。
- 汇总后检查 `卖家实收 ≥ minTotalOut`。买家抢先撤单只会让对应的单失效，卖家不会多付。
- 事件：`BidFilled(bidId, seller, q, price)`。

**`sweepFees(quote)`**：任何人都可以调用，把 `feesAccrued[quote]` 转到写死的平台地址。

### 8.4 安全要点

- 全部外部函数加 `nonReentrant`，遵循 CEI。
- 不收发原生 BNB，不存在 `receive()` 拒收导致的拒绝服务。
- 手续费记账提取，平台地址出问题也不影响成交。
- 托管采用累计差额法（§8.3），部分成交多少次都不会出现取整误差累积或下溢；撤单直接退还剩余托管。
- **开盘状态的判断**：`placeBid` 和 `fill` 每次被动读取 `hook.launched()`（一次只读调用，约 2,600 gas）。**不采用**"Hook 开盘时主动通知买单簿"，因为这会给 `launch()` 多加一个外部调用，一旦那个调用失败，就会违反"开盘一定能完成"这条不变量。
- 不变量：`sum(剩余托管) + sum(feesAccrued) == 合约余额`。

### 8.5 必须披露的两点

1. **成交价最多比最新参与价低 10%**：曲线价上涨后，价格低于这条线的旧单变成"只能撤单"。
2. **开盘前卖出可能比开盘价便宜**：卖完后成交区间约为 1.35P 到买家出价，而开盘价是 2P。

## 9. 开盘后：池子、货架阶梯、金库

### 9.1 货架阶梯

**结构**

| 项目 | 数值 |
|---|---|
| 总量 | 12,600,000 枚（占总供应 21M 的 60%） |
| 档数 / 每档 | 4000 档 × 3150 枚 |
| 第 i 档价格 | `2P × STEP^i`，`STEP = 1.001902508…`（每档约 +0.19%） |
| 价格翻倍 | 约每 365 档（约 115 万枚） |
| 最后一档 | 约为首档的 2000 倍 |
| 开放时间 | 仅开盘之后 |

**购买**

- `mintBondingCurve(数量, 最多愿付金额)`：合约新铸代币给买家，不经过池子，不推动池子价格。
- 一笔最多跨 32 档（约 10 万枚）。
- `最多愿付金额`是滑点保护。
- `quoteMint` 的预估结果与实际成交逐档一致。

**解锁条件**：第 i 档的价格 ≤ 1.05 × 参考价。

- 开盘满 30 分钟后：参考价 = min(池子现价, 30 分钟 TWAP)。
- 开盘 30 分钟内：参考价 = min(池子现价, 2P)。
- 效果：
  - 市场持续上涨，货架才逐档打开；
  - 现价一跌，高档立刻锁住；
  - 短时拉盘拉不动 TWAP，所以打不开货架。

**防操纵**

1. **同区块锁定**：本区块池子发生过交易，就不能买货架；开盘区块也锁定。
2. **平台紧急刹车**：多签可以暂停货架，单次最长 7 天，到期自动恢复；只影响货架。

**收入分配**：货架款从买家直接分给收款方，99% 给 `projectAdmin`，1% 进金库。

**市场作用**

- **给上涨踩刹车**：池子价格高于货架档时，套利者会铸币卖进池子，把价格拉回货架附近。这种套利只在池子价格高于货架价时才赚钱，不会把价格砸到 2P 以下。
- **收入和需求挂钩**：项目方只有在市场持续上涨时才能从货架拿到收入。
- **开盘即有供给**：首档是 2P，开盘头 30 分钟内 2P 到 2.1P 之间约 25 档（约 8 万枚）从开盘后的下一个区块起就可以买，所以开盘买盘会先被货架吸收。
- **规模示例**（硬顶 100 BNB）：首档约 0.09 BNB；4000 档全部卖完理论总收入约 9.5 万 BNB，但这需要币价涨约 2000 倍。

**与 v1 唯一的差别**：`SHELF_PREMIUM_BPS` 从 10500 改为 10000。

### 9.2 池子与交易税（沿用 v1）

| 项目 | 规则 |
|---|---|
| 官方池 | PancakeSwap Infinity CL，全区间，只能由 Hook 初始化 |
| LP 手续费 | 0.30%，归永久锁定的 LP 头寸 |
| 交易税 | 输入额的 1% |
| 买入税 | 0.7% 进金库，0.3% 给平台 |
| 卖出税 | 收到的项目代币全部销毁 |

### 9.3 金库（沿用 v1）

- `ToshLadderTreasury` 只能单向回购，买回的项目代币全部销毁，没有提款函数。
- 资金来源：货架收入的 1%，以及池子买入税中的 0.7%。
- `pokeBuyback` 任何人可调用，触发步长、单次花费比例、批量、深度上限、价格偏离保护全部沿用 v1 参数。

## 10. 资金流向总表

| 资金 | 去向 | 时间 |
|---|---|---|
| 创世存款 20% | 记入 `fundAccrued`，`projectAdmin` 随时 `withdrawFund()` 提到 `projectFund` | 每笔记账，随时可提 |
| 创世存款 80% | 记入 `lpReserve`，开盘时全部进池，LP 永久锁定 | 开盘时 |
| 外部误转入 Hook 的资金 | 转给平台 | 开盘时 |
| 买单簿手续费 2%（买卖各 1%） | 记入 `feesAccrued`，`sweepFees` 转到平台多签 | 每笔成交 |

| 池子买入税 1% | 0.7% 金库，0.3% 平台 | 每笔买入 |
| 池子卖出税 1% | 代币直接销毁 | 每笔卖出 |
| 未卖出的创世币 | 黑洞 | 开盘时 |

**基金会为什么改为记账提取**：如果每笔存款都把 20% 推送出去，项目方只要把 `projectFund` 改成一个拒收转账的合约，所有存款就都会失败，创世发售等于被冻结。改成记账后，存款只修改一个数字，任何地址都卡不住它；项目方随时可提，效果上仍然是实时可用。

`projectFund` 由 `projectAdmin` 随时可改，每次修改发出 `ProjectFundChanged(old, new)`，前端显示当前地址和修改记录。

## 13. 测试清单

**创世曲线**

- 单笔、多笔、跨越卖完点的成本，与解析解的误差在 1 wei 以内；舍入方向始终对协议有利。
- 卖完时 sold = 5.6M、raised = H。
- 模糊测试：单笔接近硬顶的大额买入、s 接近 C 时的小额买入，无溢出。
- `MIN_BUY` 下限；最后补齐剩余时可以低于下限。
- `DUST` 尾差直接视为卖完，`soldOutAt` 正确。

**Agent ID**

- 没有 ID 时拒绝；额度用完时拒绝；超额部分截断。
- 同一个名字换绑地址后不能重复领。
- 合约调用、7702 账户调用 `buyGenesis` 被拒绝。
- fork 测试读取真实注册表。

**资金**

- 20% 记入 `fundAccrued`，`withdrawFund` 能全额提取。
- `projectFund` 是拒收转账的合约时，`buyGenesis` 照常成功。
- 只拉取精确金额：授权额度大于成本时，余额只减少成本。
- 权限：`setProjectFund`、`withdrawFund` 只有 `projectAdmin` 能调用。

**launch**

- 卖完前、截止前不能触发。
- 48 小时内只有 `projectAdmin` 能触发；48 小时后任何人都能触发（边界：恰好 48 小时这一秒的归属要在测试中明确）。
- 开盘价 = 2P；L、黑洞数量正确；创世总量 = 8.4M。
- 只有一笔 `MIN_BUY` 时可以开盘。
- 工厂暂停、黑名单、货架刹车同时生效时可以开盘。
- 外部误转入 Hook 后，开盘价仍然是 2P，多出部分转给平台。
- 第三方用官方 PoolKey 直接调用 PoolManager 的 `initialize` 会被拒绝（`UnauthorizedInitialization`）；用其他 Hook 初始化的同币对池不影响开盘。
- Agent ID 注册表调用失败或耗尽 gas 时，`buyGenesis` 报 `AgentRegistryUnavailable`，`launch` 不受影响。

**转账限制**

- EOA 之间可以转账。
- 合约收发、7702 账户、第三方 `transferFrom` 被拒绝。
- 合约在构造函数里调用 `transfer` 被拒绝。
- 先打到空地址再部署合约后，无法转出。
- 收款地址登记：
  - 转给未登记地址被拒绝；
  - 用 CREATE2 预计算的地址无法登记；
  - 合约调用 `registerReceiver` 被拒绝；
  - 只有 Hook 和买单簿能调用 `registerFor`；
  - 创世买入和挂买单会自动登记；
  - 开盘后转给未登记地址可以成功。
- 往 Infinity Vault、V2 pair 加流动性失败。
- 买单簿的 `transferFrom` 可以通过。
- 开盘后全部恢复正常。

**买单簿**

- 挂单价低于最新参与价时拒绝；金额低于最低挂单额时拒绝。
- 成交价下限：恰好等于 90% 时可以成交，低 1 wei 时被跳过；被跳过的单可以撤单。
- 假买单：买家挂单后做 7702 委托，成交时被跳过，同一笔交易中的其他单照常成交。
- 合约调用 `placeBid`、`fill` 被拒绝。
- 部分成交、多次部分成交后托管刚好结清；撤单全额退款。
- 累计差额法模糊测试：把一张单随机拆成 1 到 1000 次部分成交，每一步剩余托管都不小于 0；全部成交后剩余托管 = 0；扣除总额 = 挂单托管。
- 极小额成交：金额向上取整；低于 `MIN_FILL_QTY` 时拒绝。
- `minTotalOut` 保护。
- 开盘后挂单、成交被拒绝，撤单可以执行。
- 手续费：买卖各 1% 记入 `feesAccrued`，`sweepFees` 到达平台。
- 不变量：剩余托管合计 + 应计手续费 = 合约余额。

**货架回归**

- 首档 = 2P。
- v1 中货架、金库、交易税相关测试全部通过。
- PoG、推荐、退款相关测试删除或改写。

**模糊 / 不变量测试**

- 随机买入、挂单、成交、撤单、开盘序列。
- 不变量：没有资金凭空产生；没有资金卡死；开盘始终可达。

## 15. 风险披露（写入白皮书）

1. **没有退款**：存款就是最终购买，开盘后价格可能跌破成本。
2. **Agent ID 不代表唯一真人**：一个 KYC 账户只能开 1 个 ID，但 KYC 账户本身可能被买卖；注册表由第三方管理，其管理员可以直接发 ID。
3. **项目基金会资金由项目方控制**：20% 资金由项目方支配，地址可以随时修改，平台不做监管。
4. **开盘前只挡链上 AMM**：挡不住链下 OTC。
5. **买单簿的价格风险**：成交价最多比最新参与价低 10%，并且可能低于开盘价 2P。
6. **开盘前受限的钱包**：合约钱包和 7702 委托账户开盘前不能参与首发，也不能转币。
7. **开盘后可能出现第三方池子**：任何人都可以另建无 Hook 的池子。
8. **开盘抛压**：卖完时参与者手里有 5.6M 枚，池子里只有 2.8M 枚；开盘时人人账面盈利，如果集中卖出，池子价格可能跌到约 0.22P。
9. **货架压制早期上涨**：开盘即有约 8 万枚货架供给，池子很难脉冲式上涨。
10. **募集很少时池子很浅**：没有最低募集额，池子深度可能只有几个 BNB，价格波动会很大。
11. **开始区块会被抢**：越早越便宜，机器人会在开始区块抢跑；有单个额度上限，影响有限。
12. **刷单可以操纵最近成交价**：自己卖给自己，花 2% 手续费就能刷出成交价。页面同时显示成交量。
13. **费用汇总**：买单簿买卖各 1% 归平台；池子交易税 1%；LP 手续费 0.3%（PancakeSwap 的协议费另计）。
14. **合约风险**：智能合约漏洞、计价币价格波动、监管变化。
