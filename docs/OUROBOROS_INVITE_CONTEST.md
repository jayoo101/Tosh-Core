# Ouroboros 邀请赛结算（操作说明）

本文只描述人工步骤。它不会自动打款，也不会把自动付款标成已经开启。公开页面上的规则以 `soat-frontend/src/lib/ouroboros/contest.ts` 里的中英文本为准，对外文字不点名更早的发售阶段。

## 规则（与页面一致）

- 时间（UTC，含开始、不含结束）：`2026-11-20T14:00:00Z` 至 `2026-11-27T14:00:00Z`。
- 报名页：`https://toshx.xyz/ouroboros`。签名申请后，Safe 签名人审核通过才激活链接。通过前的铸造不追溯。
- 新用户：活动开始前没有任何 Ouroboros 铸造记录的 Agent ID。开始前已经铸造过的地址可以当邀请人，不能当被邀请人。
- 绑定必须发生在该钱包第一次 L2 铸造之前，第一次归属不再改变，不能邀请自己。
- 活动时间内同一 Agent ID 的 L2 铸造份额累计满 30（可分多次）记一次。只计 L2 铸造，不计市场买卖。
- 每笔固定 5 BSC USDT。硬上限 6000 次、30000 USDT。顺序是打满第 30 份的区块、交易序号、日志序号。取消资格后名额按这个顺序顺延，不按报名先后。
- 暂缓复核的名额先占住位置，不打款，也不把名额让给下一位；取消之后才顺延。
- 多个钱包给同一个 Agent ID 铸造时，系统不猜测收款人，记为待复核。指定归属必须落在链上已经成立的绑定上，不能凭空补一条邀请关系。
- 同人多身份不会自动识别。人工决定写入 `ouro_ref_contest_reviews`。
- 没有用户领取按钮。Gas 由付款钱包支付，对方实收 5 USDT。
- 自动付款仍由已有的 `OURO_REF_AUTOPAY=1` 控制，每小时 `0 * * * *`（UTC）调用 `/api/ouroboros/ref/autopay`。未设为 `1` 时任务直接返回 `disabled`，不转账。单次合计超过 1000 USDT、单人超过 500 USDT、余额不足、上一笔未确认、索引不新鲜，都沿用原来的暂停条件。
- 活动结束后 48 小时内（不晚于 `2026-11-29T14:00:00Z`）公布脱敏结果；其后 48 小时可申诉（至 `2026-12-01T14:00:00Z`）。申诉处理完后的 3 个工作日（UTC 周一至周五）内付清尾款。这是人工时限：尾款仍走同一套小时任务，或由签名人在合作方页面把已经上链的付款关联到奖金。不要另做一笔没有记录的转账。

## 这次迁移做了什么

`soat-frontend/supabase/migrations/0012_ouroboros_invite_contest.sql`：

- 给 `ouro_mints` 增加可空的 `tx_index`。不改已有行的其他列。
- 把当时的 `ouro_ref_fill_rebates` 复制到 `ouro_ref_legacy_fill_snapshot`。重跑不会覆盖已有快照行。
- **不** `DELETE` / `UPDATE` `ouro_ref_payouts`、`ouro_ref_pending`、`ouro_ref_links`、`ouro_ref_bonuses`。
- 新建奖项、复核、结算关联和窗口边界表。奖项由应用写入；迁移本身不插入任何奖金，因此不会回溯发奖。
- `ouro_ref_partner_balances.owed` 改为「未关联结算的待付奖金」。旧的付款行仍然留在 `ouro_ref_payouts`，不会被当成新奖金已经付过，除非签名人显式做「关联」。
- 未结算的旧口径应计不再进入 `owed`，所以小时任务不会按旧规则把它们打出去。

## 上线顺序（本变更没有执行）

1. 在生产库只读确认 `0010` 已应用，并记下 `select count(*) from ouro_ref_fill_rebates` 和 `select count(*) from ouro_ref_payouts`。
2. 应用 `0012`。再只读确认快照行数与第 1 步的 fill 计数一致，且 payout 行数不变。
3. 部署包含本提交的前端。不要在同一步把 `OURO_REF_AUTOPAY` 改成 `1`。生产上这个开关是否已经是 `1`，以 Vercel Production 的实际值为准，源码缺省是关闭。
4. 等索引跑过之后，只读查看 `ouro_ref_contest_bounds` 是否写出了 `start_block`。活动开始前 `start_block` 可以仍为空，此时不会产生奖金。
5. 合作方页面应显示「自动付款：关闭」或「开启」，与环境变量一致。页面文字本身不表示已经开启。
6. 若确认要沿用小时打款，再单独打开 `OURO_REF_AUTOPAY`。打开后第一次运行前，确认付款钱包里的 BSC USDT 和 Gas 用的 BNB 都是打算付出的金额。私钥不写入仓库。
7. 活动结束后按上面的 48 小时 / 48 小时 / 3 个工作日人工公布、受理申诉、付尾款。取消资格用合作方页面的复核，不要直接改 `ouro_ref_payouts`。已经广播的转账不能靠取消资格退回；名额会顺延给下一位，因此应在打款前把可疑项暂缓。

## 不要做的事

- 不要为了本活动删除或改写已有付款、待确认交易或邀请链接。
- 不要把快照里的旧应计再导入待付。
- 不要在申诉结束前把暂缓项批量改成可付，除非复核记录已经写好。
