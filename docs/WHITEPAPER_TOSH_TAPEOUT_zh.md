## 1. 摘要

ToshX 是 BNB Smart Chain 上的公平发射平台：Binance Agent ID 定额度、线性曲线创世（P 到 1.5P，以 2P 开盘）、永久锁池、4,000 档货架持续发行，货架收入 **99% 归项目方**，1% 进入单向金库回购并销毁**该项目代币**。规则写在合约里，详见主白皮书。

TapeOut 是面向可验证计算与生产工具的协议：建设者创建 **Processor（厂牌）**，发行晶体管，流片为可重放求值的电路，并以 Proof of Design（PoD）等方式证明真实设计投入。

二者结合的目标只有一句：

> **TapeOut 证明「建设者是谁、做过什么」；ToshX 负责「钱怎么募、收入归谁」。**

结合发生在**产品层**：申请时可自愿登记 Processor 与链上说明，目录与详情在有数据时展示工程痕迹。  
结合**不发生在资金层**：不强制创建 Processor，不锁定货架收入做里程碑，不要求平台回购或贡献 BEM，不改写任何金融合约路径。

未接触 TapeOut 的项目，发射路径与资金规则与今日完全相同。

## 2. 为什么要结合

### 2.1 发射台缺「建设痕迹」

审核制能挡住明显的空壳，但参与者在详情页往往只能看到叙事与链接。链上若存在可核验的厂牌、烧毁量与流片记录，就能把「认真做过东西」从口号变成可点击的证据——**而不必改变打新与货架的定价**。

### 2.2 建设者缺「公平融资出口」

TapeOut 侧的工具、电路与应用需要启动资金与流动性；ToshX 已提供零预挖、永久锁池与持续货架收入。二者对接时，建设者应能**自愿**展示厂牌，而不是被要求再发一套与融资无关的资产。

### 2.3 必须避免的两种错误

| 错误 | 后果 |
|---|---|
| 把结合做成「必须回购 BEM / 必须开 Processor」 | 扭曲 ToshX 作为中立结算层的定位；抬高所有项目的成本 |
| 把货架 99% 再抽去「生态义务」 | 破坏「项目方收入与持有人同向」的核心承诺 |

本白皮书选择第三条路：**可选展示、资金规则不动。**

## 3. 分工：谁证明什么、谁结算什么

| | TapeOut | ToshX |
|---|---|---|
| 核心能力 | 可验证计算、厂牌、晶体管、电路、PoD、`tape://` / DeWEB | 公平发射、Agent ID 准入、永久底池、货架、Circuit 收入权、项目币回购销毁 |
| 回答的问题 | 这人是否设计过、规则过程能否重放、说明是否在链上 | 额度如何分、募资是否公平、钱付给谁、池子能否被撤 |
| 本结合中的角色 | **身份与工程证据的来源** | **募资与结算的执行** |
| 不是 | ToshX 的替代发射台 | TapeOut 协议的分叉或义务做市商 |

ToshX **不**充当 BEM 的义务买方，也 **不**在 Hook 内实现门电路虚拟机。

## 4. 设计原则

1. **结算优先于叙事。** 任何生态故事不得修改货架分成、募集资金分配（80% 进池、20% 项目基金）与锁池。  
2. **可选优于强制。** Processor、工程指标、`tape://` 均为选填或按数据出现；缺失不阻断发射。  
3. **名实分离。** 「Circuit NFT」与 TapeOut「电路 / Processor」名称相近，合约与权属相互独立；结合仅为登记与展示。  
4. **失败降级。** 外部索引不可用时，隐藏工程模块，不阻碍打新与交易。  
5. **写清不做。** 里程碑锁款、BEM 强制贡献等一经排除，即不在路线图中伪装成「即将上线」。

---

## 5. 关键概念：Processor、电路与 Circuit NFT

### 5.1 Processor（厂牌）

在 TapeOut 中，Processor 是链上的**芯片厂身份**，而非电脑 CPU，也**不是**项目方必须再发的第二个代币：

- 创建者设定晶体管总量与铸造价格（上链后固定）；  
- 他人铸造晶体管时，费用归该 Processor 的受益人；  
- 设计完成并 tape out 后，晶体管被烧毁，留下可求值的永久电路。

| | 项目代币（ToshX） | Processor（TapeOut） |
|---|---|---|
| 用途 | 募资与交易 | 厂牌、零件供应、挂载电路 |
| 是否必需 | 发射必有 | **可选** |
| 收入 | 货架 99% 等（见 §6） | 晶体管铸造费（在 TapeOut 侧领取） |

### 5.2 电路（Circuit）与 ToshX Circuit NFT

| | TapeOut 电路 | ToshX Circuit NFT |
|---|---|---|
| 是什么 | 烧毁晶体管后留下的、可 tick 求值的永久逻辑 | 控制 `CircuitRevenueVault` 的 ERC-721，领取货架等收入 |
| 本结合中的关系 | 可作为工程展示的外链对象 | 发射时由工厂铸给 `developer`，规则见主白皮书 §12 |
| 是否自动同步 | 否 | 否 |

对外表述禁止使用「发射还要再发一个 Processor 币」之类说法。

## 6. 资金归属（不变）

结合层**零改动**下列规则（与主白皮书一致）：

```
货架成交
  ├─ 99% → 项目 Circuit 收入金库（项目方持 Circuit NFT 领取）
  └─  1% → 平台回购金库 → 买入并销毁【该项目代币】

交易税（方向性摘要）
  ├─ 买入：部分进入回购金库（项目币）、部分进入平台手续费地址
  └─ 卖出：项目代币销毁
```

含义：

- 货架收入在经济实质上归项目方（99%）；1% 用于该项目自身的通缩，**不是**购买 BEM。  
- 平台不得、本方案亦不会默认锁定或截留货架 99% 用作「生态里程碑」。  
- Processor 铸造费与 Circuit 金库是两套收款口；若建设者两者皆有，由各自协议规则领取，ToshX 不归集。

## 7. 结合层：选填身份与工程展示

### 7.1 申请时选填

在现有审核制申请（如 `/apply`）中增加可选字段，例如：

- Processor 地址与所在网络；  
- `tape://` 或容器说明链接；  
- 其他可核验的工程链接。

不填亦可提交。填了则由运营核对链接有效性后写入项目索引。**链上 `createLaunch` 参数不变。**

### 7.2 目录与详情展示

当且仅当索引中存在有效绑定或可拉取指标时，渲染「TapeOut / 工程」区块：

| 展示项 | 行为 |
|---|---|
| Processor | 外链至厂牌页 |
| 晶体管烧毁量、PoD 成绩等 | 有数据则显示 |
| 链上说明（`tape://`） | 项目提供则显示 |

无数据或拉取失败：**不渲染该区块**，不影响创世买入、交易与货架。

### 7.3 关于「Tape-In」

若产品保留 Tape-In 等运营标签，其含义为「偏生态建设者」的展示分类，**不以登记 Processor 为硬性准入条件**。

### 7.4 鼓励但不强制的说明镜像

项目方可自愿将合约地址与说明部署于 TapeOut 的 `tape://` / DeWEB 容器；官网作为浏览器对照，有助于缓解前端被篡改时的信息不对称。无镜像不构成发射障碍。

---

## 8. 明确不做的事

下列事项**不在**本结合白皮书的交付与承诺范围内：

1. 以电路输出解锁里程碑拨款，或锁定货架收入；  
2. 将「上架 BEM 回购金库」或「平台收入定期购买 BEM」作为标配义务；  
3. 强制每一发射创建 Processor，或链上强制同步 Circuit NFT 与 Processor 所有权；  
4. 修改货架定价、反操纵天花板、金库无提款设计或 `createLaunch` 金融逻辑；  
5. 在 ToshX Hook 内实现 NAND/LATCH 虚拟机，或以跨链电路实时驱动货架铸币。

剔除上述项，是为了保护 §4 与 §6 的原则不被「生态叙事」侵蚀。

## 9. 参与者体验

| 角色 | 结合后的变化 |
|---|---|
| 普通参与者 | 打新、买单簿、交易、买货架路径不变；若项目填写了厂牌，多一个可点开的核验入口 |
| 未使用 TapeOut 的项目方 | 申请与发射负担为零增量；收入规则不变 |
| TapeOut 建设者项目方 | 可自愿展示 Processor 与工程指标，便于社区区分「有流片痕迹」的团队；铸造费仍在 TapeOut 领取 |
| 平台 | 审核时多一项可选核对；不因此获得货架资金的额外支配权 |

## 10. 治理与边界

- 上架与紧急制动仍遵循主白皮书 §14：Safe / 发射网关；开盘不需要平台权限（主白皮书 §8.4）；刹车只能停「新增」，不能扣住任何人已买到的代币或已投入的资金。  
- 结合层数据存于申请库与项目索引，属产品配置；**不能**覆盖链上 `projectAdmin`、金库余额或回购出口。  
- 治理 Safe 不因本方案承担「维护 BEM 价格」或「代管 Processor」的义务。

## 11. 路线图

### 11.1 结合层交付（产品）

| 阶段 | 内容 |
|---|---|
| 第一期 | 申请选填 Processor / 说明链接；审核可见；目录与详情条件展示 |

预计以周为单位由前端与运营落地，**无需合约升级**。

### 11.2 规划中、需另开决策的方向

> 以下**不是**本版本承诺。

- 在数据源稳定后，将 PoD / 烧毁量作为 Agent ID 之外的补充准入或展示信号；  
- 可选的链上 registry（`hook → processor` 事件）供多前端索引；  
- 在 TapeOut V2（如高级元件）成熟后，再评估「只消费输出、不改结算」的只读集成。

## 12. 已知局限

1. **结合层不是链上硬约束。** 展示可被前端或索引错误影响；资金安全仍只依赖主白皮书中的合约规则。  
2. **外部依赖。** Processor 与指标依赖 TapeOut 网络与公开数据的可用性。  
3. **同名易混。** Circuit NFT 与 TapeOut 电路需持续教育，避免参与者误以为收入权等于流片电路。  
4. **审核仍是瓶颈。** 选填身份不能替代主白皮书中的上架审核制。  
5. **历史项目。** 早期以 BEM 计价开池的项目保持其原有池子与回购安排；本结合不对其施加新的 BEM 义务，也不要求补建 Processor。

---

## 13. 结语

ToshX 与 TapeOut 的结合，应当让建设者更容易被看见，而不是让结算层背负异族代币的做市义务，更不是把项目方的货架收入重新变成平台可以挪动的「生态预算」。

因此本白皮书主张：

- **身份可选**：Processor 是厂牌，不是第二融资代币；  
- **结算不变**：货架 99% 归项目方，1% 只服务于该项目币的销毁；  
- **展示降级**：没有工程数据时，协议体验与今日一致；  
- **边界写死**：不做里程碑锁款，不做 BEM 强制贡献，不改金融合约。

协议层的公平，仍然以主白皮书为准、以链上调用为准。  
结合层的意义，是给愿意被核验的建设者一块铭牌——挂或不挂，由项目方自己选择。
